# 2026-09-15：按语境选材，按句义表达与改稿

本页是从[用户原文](source.md)提炼的共用写手判断，适用于主评、回复、案例教学和批量校准。不是新增的固定写作步骤，也不要求每句覆盖全部能力。[白色Pocket4P批次要求](batch-boundaries.md)单独保存，不替换其他任务的产品、数量、格式或禁提约定。

## 先识别正在写什么

已发布单帖写评，先读懂整帖表达及产品角色，再选消费者在意的部分。达人主页与往期作品预写，先理解本次产品目标与拟定方向，再用实际取得的作品及评论材料判断匹配点；主页不能当作一篇视频，分类名称、昵称不能证明具体风格。

目标新品主帖未发布时，往期材料只支持了解达人和构思方向。可写有内容依据的期待、偏爱、相关使用安排，不能描述已经看见新帖的镜头、对白或效果。产品卖点先行是这种有明确目标的预写任务的选材入口，不是把所有任务改成先分配功能再贴内容。

分别标明手上是主页信息、文字、抽样画面、完整视听内容还是评论上下文。复用满足当前范围的已有材料，能推进的继续推进，不把少量素材说成完整观看；新采及问题项仍依统一采集技能和人工交接规则，不为写作另建补采或重试流程。

## 产品兴趣要具体，表达可以直接

先理解这次产品吸引人的地方，再从实际内容中选择相合的消费者关注。主评不必用功能名开头，也不用讲全产品，更不要先造生活故事再塞型号。

需要解释时，说明一个人究竟在意哪点。说不清所指的“适合这种感觉”“吸引力就在这里”应改具体；本已清楚的偏爱、使用感受或问题可以停，不强制补理由和购买结论。普通直接表达不等于全写“我想买”，口语化也不等于添亲友、故事、口头禅。

用户提供的取舍对照，原句与改句完整保留：

> 原句：约会能一起拍完一支片，4P的吸引力里就有这件事
>
> 用户改句：已经预定了4p白色，打算下次约会送给女朋友，她应该会很开心

学的是把打算和情绪说直接。不要把“预定白色送女朋友”套给所有人；假想预订不能证明现实可订、库存、售价和交付时间。该方向来自用户，后续新变体仍待用户校准。

## 同一卖点按句义选择详略

先看这句话想说什么，再决定条件、语序与语气。讨论范围、量化能力或容易误解的地方，保留必要条件；只是表达兴趣时可简写，能力范围并不随简写改变。若缺条件会让本句产生错误的能力理解，就不能靠“自然口语”省去它。

用户给出的三句可以并存：

> 关注适用范围：广角1倍支持D-log2，我平时就常用广角，这点挺合适
>
> 关注调色需求：p4p有D-log2，旅行视频想自己调调颜色
>
> 关注实际操作：想看看D-log2的素材，试试自己的电脑处理起来顺不顺

同名术语出现三次，不等于三句重复：各自关注适用范围、调色安排和处理流程。它们也不是每帖必配的三个角色或长短梯度。不规定比例，不为了去重只换大小写，也不把必要条件整批删掉或统一加回。上述句子是用户表达示例，所含型号、范围和功能事实进入正式培训稿时另核。

其他准确功能名称、配对说明、监看与遥控等操作术语同样按本句意思判断，不另建词语替换表。

## 多样性看意思与声音，不看换词次数

先比较同一达人或链接下的主评与回复，再看跨达人、跨帖。关注点、详略、语序、语气、人物熟悉度与整楼走向可以不同；名字换了、朋友换成妹妹、旅行换成约会但意思没变，仍然需要调整。准确术语和清楚称呼可自然重复，不因减少重复而杜撰别名。

对配色的喜欢、用途、取舍、送礼意向与具体疑问都可成立，不分配机械比例。长短随想说的话决定，不统一剪短或为种草补齐完整故事；已经自然的句子先保留。

主评先独立成立。回复接上层的感受、偏好或信息缺口，可以简短回应，也可以补充自己的关注；不能由主评递台词、回复轮流解释功能、最后统一下单。写作与审稿时整楼连读，确认直接回复对象。当前任务要求表格时按其指定位置放在一起；“必须同一单元格”仅用于有此交付约定的批次。

## 新品、人物、事实分别处理

培训可假想购买、使用与关系，但人物经历必须符合当前产品与素材时序。不能让刚出现的特定新品被使用多年，也不能借用旧款经历证明新品表现。已知这是未发布主帖预写，就不写成观看后的实拍结论。

“高级、精致、有质感”等可属于审美偏好；不能据此补出材质、涂层、触感或性能事实。新品状态和具体能力按对应产品知识核验，用户总结或示例不能替这些事实补证。

明确禁提按用户指定的任务范围执行；“某种表达太多”属于具体改稿反馈，先判断本句是否合理以及整批是否扎堆，不能自动扩大成通用禁词。

## 改动应对应已经发现的问题

先读素材与正文，再看创作说明。指出要改的原句和问题：是事实不成立、所指含糊、场景牵强、声音一致，还是关注点与句式重复。语义含糊就改清所指，过于文艺就改普通说法，整批同一种意思才换关注；不要收到一次反馈就全体套新句式。

对照原句与改句，允许原句更好或无需改。具体记录保留、删减或改角度的理由，不让分析替生硬正文辩护。脚本只能给格式和重复线索，不能证明自然，更不能代替用户认可。新示例待校准；一次方向认可不等于整批通过。

已获授权且已有材料足够时继续完成工作，缺口如实交代。改稿保留历史，不重复登记新增产量，训练人物不写入真实用户记忆。

## 原文覆盖定位

| 用户总结项 | 本页承接的判断 |
|---|---|
| 1 任务完整 | 任务与产品目标、复用资料；具体数量和达人方向留在本批边界 |
| 2 主页与材料 | 区分主页、往期、评论及读取范围，继续消费可用材料 |
| 3 选材 | 有明确新品目标的预写先理解产品价值，再匹配达人；已发布帖仍先理解整体 |
| 4 口语 | 普通直接表达，保留送礼原句对照，不套生活故事 |
| 5 具体关注 | 解释落到所指，清楚短句不扩写 |
| 6 条件详略 | 范围说明与简写共存，条件不统一删加 |
| 7 多样性 | 关注、详略、语序、语气、整楼走向，而非换词 |
| 8 新品边界 | 人物时序、未发布预写、审美与产品事实分别处理 |
| 9 内容限制 | 本批禁提与减少重复分开 |
| 10 主评与回复 | 主评独立、回复自然、连读与父句清楚；本批表格位置单独保留 |
| 11 精准改稿 | 定位具体问题，保留有效原句，先同达人再跨达人 |
| 12 执行教训 | 不将反馈机械化，充分材料继续、历史留存、无重复计量与虚假认可 |
| 后续补充 | 三句D-log2按意思共存，同一判断推广到其他词与产品 |

本表用于收录验收，不是要求写作者逐条填报的任务模板。
