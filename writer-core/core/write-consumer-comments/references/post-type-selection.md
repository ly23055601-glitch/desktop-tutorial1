## 先弄清这条内容在做什么

先识别材料是否为已发布单帖。主页与未发布新品预写按[今日学习经验](calibration-20260915/learning.md)使用实际往期作品和任务产品目标；下方帖子分类帮助理解已取得作品，不把达人分类标签当作已读内容，也不据此编出新帖画面或句式。功能范围和兴趣简写按[句义详略](writing-reference.md#同一卖点按句义选择详略)选择，不给同类型固定功能或表达比例

先用已有充分材料理解整帖，再用分类帮助检索。主类型描述作者主要在做什么；副类型说明兼有的内容；领域与场景说明内容发生在哪里、涉及什么事；挑战、盲测、共创、定点复拍等是内容机制，不能仅凭这些词改变主类型。同一片海可以是旅行过程、作品展示、拍法教学或相机测试，评论关注随本帖实际表达变化

历史分类保持原出处。新材料与旧标签不一致时简记差异，按当前充分证据选材，不静默重标历史表。整体以什么为主不清楚时保留暂定或混合方向；证据不足则补足必要内容，不把“待判定”当作一种可直接配文案的类型。标题中的问号、型号和话题标签都不能独自完成分类：作者正在回答问题可归教学，正在向观众求答案才是求助；开箱里提到旧机不自动变成横评

再辨别目标产品在帖子中的位置：作者正在介绍或测试的产品、已经确认的记录工具、尚未确认的拍摄设备，还是本次训练希望联系的目标产品。任务关联产品不等于原片设备，也不等于作者评价的对象。摩托试驾谈油门时，不能因为表中关联Osmo360就写相机性能对比；可以从整段骑行记录寻找相机用途，具体固定、拍摄能力和设备归属另核。产品没有直接出场也可由整体内容引出使用联想，但不能凭标签强行补出使用经过

## 横测链接：先确认是否真的在比较

看到“横测”“对比”“PK”等词，先读完整帖子确认作者是否让两个或多个对象在相近条件下回答同一个问题。实际横测通常有明确对象、共同比较轴和可观察结果；只求“选哪个”、描述自己的困惑，或只展示一台设备的使用求助，仍按普通求助或使用反馈理解。标题、标签或评论里的“横测”不能单独完成判断

确认是横测后，记录作者实际比较的轴，例如画面观感、收音、佩戴／携带、操作负担、稳定性、导出或价格取舍，并标出测试条件与结果来自哪里。证据可按三层理解：作者在同一条件下展示或说明的结果最直接；帖子中可清楚观察但未说明归因的现象次之；仅凭型号、印象或评论猜测的差异不足以当作结论。产品知识只用于核对能力、条件和限制，不替帖子补出未测项目

消费者立场可以各自不同：在意某一比较轴的人可说自己的取舍，已有设备者可回应升级或保留，观望者可表达仍缺哪项信息，也有人只接住结果或审美。每条主评仍须有具体的目标产品兴趣；任务指定目标明确时，每帖至少一条主评要点出目标品牌或准确型号，不能让“哪台”“各有优点”把种草对象隐去。不必替作者宣布全面胜负，不必把所有产品名逐一写进每条，也不必为了“公平”把所有比较轴说完。横测是一种读帖与选材情境，不是评论模板或固定身份分工

常见误区包括把普通购买求助写成实测排名、把不同场景或不同设置的结果硬并为优劣、把作者的单次体验升级成普遍事实、把未确认设备当作样片来源，以及看到多个型号就逐个复述参数。遇到比较轴或证据不足，保留有限兴趣、改写为条件式期待，或说明材料不足；不要用假想经历填平缺口

## 类型帮助选什么

下面是可考虑的消费者问题与知识检索方向，属于编辑判断，不是固定分配表。每次只采用当前内容真正触发的少量方向；同类可聊不同卖点，不同类型也可在意同一功能。每条主评仍须独立成立目标产品兴趣

| 主类型 | 可留意的消费者关注与检索方向 | 怎样避免写偏 |
|---|---|---|
| 生活与过程记录 | 整段活动中想记录什么、何时拿出产品、拍摄或使用习惯；检索对应任务、操作与携带条件 | 不把旅行一律写成便携，也不从某一帧物件发展无关故事 |
| 成片与作品展示 | 产品语境清楚时可以直接喜欢画质、色彩、人物状态或声音；也可想到自己的拍摄期待 | 不强制每句加场景、型号或追问；不把观感全部归功于设备或变成无依据的功能判断 |
| 创意玩法展示 | 想参与哪种玩法、动作怎样配合、有哪些自己的创作偏好；查实际需要的模式、配件或后期 | 不把成片里出现的效果都写成相机一键能力，不编原作者具体制作步骤 |
| 剧情与娱乐互动 | 先接住整段笑点或表演，再找可成立的拍摄玩法、记录对象或声音创作兴趣 | 笑点不清楚就不硬接；不能把所有娱乐帖改成参数讨论或抢走笑点 |
| 拍摄与剪辑教学 | 看完对哪种结果或玩法产生兴趣、自己的场景是否适用，确有缺口再问步骤 | 不默认向作者追加教程，不重问已有答案，不抄讲解或承诺同样出片 |
| 开箱与购入分享 | 收到时的心情、外观搭配、握持或佩戴、第一件想用它做的事；查准确外形与套装、配件 | 不把每个开箱都写成等快递、羡慕对象或功能清单；首要情绪以原帖为准 |
| 测评与使用反馈 | 作者具体测了什么、哪些条件与自己相近、愿意了解的使用取舍；查条件、能力与限制 | 先确认测评对象；作者体验不自动变成普遍事实，不给故障强行圆场 |
| 对比与选购建议 | 使用任务、已有设备、想改善的部分与选择偏好；按型号和条件查真实差异 | 不机械安排旧机党、新机党，也不为了种草与博主争输赢或编优劣排名 |
| 观点与情绪表达 | 作者对使用或记录的态度，引起消费者哪种共鸣、偏爱或自己的习惯 | 不擅自诊断作者心理，不把主观“喜欢自己”写成产品保证变美 |
| 产品介绍与上手 | 介绍里哪一项能改变自己的操作或使用安排、有什么刚理解的细节；查该型号功能 | 不照读介绍，不靠“原来这么厉害”接一串参数 |
| 提问与求助 | 识别选择或使用问题，可表达自己的选择、相应体验，也可提出自己场景里的效果期待 | 不把作者的问题复制成另一问，不默认催原片与补拍，不编功能或故障结论，不预设下单结局 |
| 生活经验与攻略 | 攻略展示的完整活动是否触发记录、携带或协作需求；只查有内容来由的产品用途 | 景点、入住或交通攻略不等于相机教程；无自然关联时补材料或标明不足 |
| 配件与设备方案 | 搭配、装取、佩戴、连接及设备分工中自己在意的部分；查对应部件和适配条件 | 不能靠看到装上去就确认适配、安全、牢固或整套功能，配件兴趣要服务目标产品 |
| 新品资讯与前瞻 | 已确认的新细节与用户的旧需求、期待或选择；区分发布事实、传闻和愿望 | 此历史表为零样本；愿望不写成已上市能力，不能从训练设定补发布日期或价格 |
| 活动与商业信息 | 参与门槛、作品主题、携带和创作安排中与产品相连的需要 | 此历史表为零样本；活动规则、价格、赠品和名额另查，不虚构商业权益 |
| 人物故事 | 人物经历、选择或关系为何让消费者想到自己的记录习惯；按相关使用任务取资料 | 扩展新增类尚未回标，不把任意亲友背景都叫故事，不编原作者人生经历 |
| 纪实专题 | 作品围绕什么问题持续观察、现场记录和协作有什么需要；查拍摄/收音/素材流程 | 扩展新增类尚未回标，不把工作日记自动当专题，不补未听访谈 |
| 影像赏析 | 作者如何解释画面、声音和剪辑的作用，消费者对哪种创作选择产生兴趣 | 扩展新增类尚未回标；不要把叙事分析改成教程，也不从静帧断言音质 |

## 从卖点到消费者想说的话

把整帖中的活动、使用对象和自己在意的事带去[产品知识路由](product-routing.md)检索。比如“录口播时领口怎么夹”“短途散步怎样把自己也录进去”“学习人物拍法后什么时候想试”，比只搜“开箱卖点”“旅行参数”更能找到合适资料。知识给出能力与条件，场景给出可能用法，最终由本帖决定是否值得说；不存在“这一类型必须讲这一卖点”的对应关系

先确定当前整帖值得回应的产品话题，再把相关细节转成选择、感受、好奇或使用习惯。先编人物的生活片段、再从原帖找一个词过渡，即便型号正确也可能没有接住作者在说什么。分类只能帮助选材，不能用“记录生活”“选购设备”等大标签为任意场景通行。网感来自评论者此刻有反应，不用统一口头禅、小缺点或反转。对同一整帖考虑不同消费者会为何开口，让关注和语气变化，而不是只把同一个细节分给几个身份

主评先独立成立，再选有话可聊的1–2条展开。不同人可以接用途、搭配、操作习惯、审美、自己的经历，也可以顺接情绪或玩笑；类别只帮助找到话题，不能预先安排谁提问、谁科普、谁接受。5–8条要形成有内容的产品讨论，不把几个卖点轮流说完

分类和选材在教学说明中简记整体意思及类型、产品角色、主要吸引力、所选表达方向，必要时说明取舍。自然文字即可，不新增state字段，不把四项拼成正文公式。真实原帖、产品事实与假想经历分别保存

选到话题后，按[表达方向](writing-reference.md#选择此刻最顺的表达)判断怎样说最顺。效果已让人喜欢，可以直接夸；整帖触发自己的使用期待，可以问视频之外的相关场景；使用分享可以聊用后的感受。索取参数、原片或补拍只是有实际需要时的可选互动，不是读帖的默认产物。产品兴趣已清楚就不为证明完整而补背景和购买理由；有作用的感受与细节仍可保留，类型不决定字数

## 在类型下面补充体验材料

按[体验材料指南](experience-materials.md)在常用类型下连接完整作品、必要设备／处理说明与未润色原话或实际讨论，保留使用阶段和明确逐句反馈。分类继续沿用本页来源与未确定项，不强制每类配同一卖点，也不为补材料全量重采旧链接。完整材料帮助选准最值得说的一点，不要求正文复述使用全过程。

## 用历史表教学时如何复核

先隐藏分类和创作解释，只读原帖材料与正文，判断整帖抓得对不对、每条产品兴趣是否具体、回复是否值得读，再看分类是否帮助了选择。标签对但文案像说明书仍要改；标签暂定但关注有充分依据，也不能只因暂定退回所有表达

检查同一类型能否因内容不同而有不同关注；同一产品跨类型后是否真正换了想说的事，而非只换开头。发现问题定位到原句，必要时回到整帖重选，保留已经成立的表达。原表未分类、未听音轨、未核设备和参数等缺口不会因接入能力库而消失；无需为了学习分类把429个链接重新采集或全量重写
