# 培训草稿与轻量state协议

本协议只用于 `content_mode=training_fiction` 的**培训用假想消费者草稿**。购买、持有、使用、关系、主观感受可以属于虚构人物，不需要为这些人物寻找或伪造真实用户证明。原帖内容及产品事实另有真实证据责任；人物设定不能充当这两类来源。`synthetic_post` 仅表示明确标注的合成训练材料，不能冒充已经采集的现实平台帖子。

CW5.4.2沿用原state字段与`--profile cw5`。达人新品预写的来源保存已取得往期材料与用户拟定方向，明确新帖尚未发布，不能将计划中的效果登记成已观察的`post_fact`。人物时序与新品一致，审美词不替材质／涂层补证，假想预订不证明库存／交期。用户指定480独立主评、回复另计或同单元格等批次要求时另核实际数量与布局，不冒充默认2–4条结构通过，也不永久改动检查器范围

## 新对话怎么填

1. 先取得用户提供的原帖材料或按相应读取技能取得的证据包，将本次实际可用材料保存为UTF-8证据文本。保留链接/材料ID、可见文字、必要画面描述、来源定位与读取限制；已有文件可直接引用。来源不能凭空补写。产品事实另存已核验的产品证据文本。
2. 按当前帖子写最终编号MD。数量沿用CW5：以每帖3–4条主评为主，确实只支持两个独立角度时可写2条并说明；通常选择1–2条主评各展开5–8条评中评，其他各0–4条。CW5.3允许产品语境清楚时直接喜欢已展示的效果，包括不点名、没有场景故事的短赞叹；不能以这些省略退回。CW5.4横测链接先确认实际对照关系、比较轴和证据，再按消费者立场选材；不要求每条复述所有产品或参数，短中长自然变化和分歧交流不改变接口。无关泛夸、跨帖重复赞叹仍复核。场景期待可超出原帖具体地点，不强制改成向博主要材料。内容判断依语义审稿，不增加字段、关键词或篇幅门槛。人物身份不出现在对外前缀中。
3. 复制 [state模板](../schemas/training-state.template.json)，按实际帖子和回复增删结构。模板只有一组字段示意，不代表主评、回复、人物或断言必须取这个数量。删除未使用的示意来源，替换全部占位内容。所有路径相对**state文件所在目录**。
4. 将每帖来源、人物设定、回复直接父句和事实断言绑定到最终正文。事实断言的 `text` 必须实际出现在对应评论中，不能登记一条无关句子代替审稿。没有需引用的事实时 `assertions` 可为空，但须语义复查是否漏标。
5. 对最终MD原始字节计算SHA-256，填入 `draft_sha256`，新稿显式使用下方 `--profile cw5` 检查命令。每次改正文后重新绑定hash。结构通过后仍须审阅事实依据、上下文、人物区分和语言自然度；不得称脚本已经证明真实或全面验收通过。

## 最终MD格式

批次页恰好有一次 `培训用假想消费者草稿` 标识。章节标题里的定位与state的 `title` 逐字一致，`section` 对应章节号；`id` 保存真实原帖ID或明确的用户材料ID。state帖子顺序与MD章节顺序一致。

```markdown
# 培训用假想消费者草稿

## 1｜原帖链接或用户材料定位

1. 第一条主评正文
    - 这条回复的正文
    - 下一条回复的正文
2. 第二条主评正文
```

此段仅说明编号语法。每帖主评从1连续编号，回复统一四个空格缩进、单层 `-` 列表，不写A/B标签、不另写回复编号、不嵌套列表。每条正文放在一行。内部ID由解析器按显示位置自动生成：主评 `1`、`2`；主评1下的第1/2条回复为 `1.1`、`1.2`。ID在每帖内独立。

正文不使用中文或英文句号；主评编号点、小数点和HTTP(S)链接内的点不算句号。英文产品名使用本帖 `english_aliases` 已登记的无内部空格写法，例如 `Pocket3`、`DJIMic2`、`OsmoMobile7`。没有英文产品名时数组可为空。脚本按登记别名检查拆空格，审稿还须检查是否漏登记或写错型号，不能以空数组绕过。`product_line=pocket` 的正文禁用 `Osmo`；该限制仅作用于当前Pocket帖子，不传递给Mic、Nano、OM、360或其他产品线。其他具体产品约束按当前产品资料与技能审阅。

## state字段

顶层只有 `content_mode`、`draft`、`draft_sha256`、`posts` 四个必要字段。CW5不新增state版本或profile字段；数量配置由检查命令或函数参数显式选择，记录在检查报告中。无需移植旧Pocket大型状态，也不写 `passed` 或虚构已完成验收。

| 每帖字段 | 填写方式 |
| --- | --- |
| `section` / `id` / `title` | MD章号整数 / 原帖或用户材料ID字符串 / MD标题中竖线后的原文 |
| `product_line` | 本帖真实产品线；Pocket写 `pocket`，其他产品写对应线路，如 `mic`、`nano`、`osmo_mobile`、`osmo360` |
| `sources` | 来源键→`{kind,path,description?}`；至少一个 `post` 或明示合成的 `synthetic_post`，需要产品事实时另加 `product` |
| `english_aliases` | 正文英文产品别名数组，内部无空格，按当前型号核验 |
| `personas` | 内部说话者→假想设定的字符串对象；不需要人物设定时可为空 |
| `reply_context` | 回复ID→`{speaker,parent_id,parent_speaker,parent_text}`；无回复填 `{}` |
| `assertions` | 最终正文的事实/可选假想经历记录数组；每条格式见下 |

`sources.path` 指向可读取的UTF-8文本，`description` 可记来源定位和限制。建议每帖使用独立的原帖证据文件；若读取技能交付整批文件，先按原帖定位提取为独立文件，并保留整批来源定位。检查器检索所指文件全文，不会识别同一文件里哪一段属于另一帖，不能把整批全文注册为每帖来源来绕过定位。截图可将可见文字/画面描述记录为 `post` 证据，并保存原图定位；不能把纯画面描述当音轨转写，不能从画面推导未证实参数或因果。用户提供的充分截图描述本身也可以是原帖材料，无需强制再次采集。视觉证据是否足以支持某句话由语义审稿判断，脚本不会把“是视觉材料”一律判失败。

`synthetic_post` 须在 `description` 和对应MD章节标题中明确写“合成”或 `synthetic`；它只支持该合成材料的 `post_fact`。`product` 始终是实际核验的产品资料，不能因模式是培训虚构就编造参数。来源性质、链接真实性及引用是否足以支撑结论依靠语义核验，文件存在不等于来源可信。

训练state和最终草稿不能作为原帖或产品事实来源自证。检查器会拒绝任何来源路径解析后指向本次state文件或最终MD，包括指向它们的符号链接；把人物设定写在state或把断言写进草稿，都不能据此获得事实依据。

`reply_context` 必须覆盖每一条实际回复，包括长讨论的第5–8条。`parent_id` 指向同楼已经出现的主评或回复，`parent_text` 逐字保存该直接父句；`speaker` 与 `parent_speaker` 对应 `personas` 中的假想人物键，且同一评论的说话者映射一致。多个说话者可以分别接主评，同一说话者可以再次发言，也可以接同楼更早的非相邻回复；不硬性要求A回来、不要求每次增加信息、不要求固定收尾。对外仍为单层缩进，不因内部父句关系增加嵌套层级。

CW5.3不改变此接口。短问、感受、偏爱与简短附和可以进入展开楼，仍绑定实际父句；普通问题、主观喜欢不为凑记录虚构事实断言。主观“喜欢这颜色”不自动成为产品事实；声称某功能造成该效果，或断言可用模式、兼容、量化性能时仍需product来源，原片实际内容另需post来源。长度、三段式与列举仅作复核线索，不新增机器自然度评分。

2026-09-15表达修订：同一功能的不同关注可合理并存，准确术语重复不单独作为同质化失败理由。主评和回复按[句义与术语详略](writing-reference.md#同一卖点按句义选择详略)审阅：简写仍核验实际写出的能力断言，完整条件保留在证据中；条件是否需写入正文取决于本句理解，不要求每次照抄全部限定。不新增词频、比例或统一替换规则，现有state与检查接口保持不变

只有实际写了回复才添加对应人物及上下文，例如：

```json
{
  "personas": {"A": "假想消费者，喜欢拍日常", "B": "假想消费者，关心握持感"},
  "reply_context": {"1.1": {"speaker": "B", "parent_id": "1", "parent_speaker": "A", "parent_text": "逐字复制实际主评1正文"}}
}
```

有产品事实时，在该帖 `sources` 中按需加入一项，例如 `"spec": {"kind": "product", "path": "evidence/product.md", "description": "实际产品资料的链接、型号及核验定位"}`。这些均为字段示意，不是每帖固定角色、对话或产品引用数量。

断言格式为：

```json
{
  "comment_id": "1",
  "text": "对应正文中的实际断言片段",
  "kind": "post_fact",
  "evidence": [{"source": "original", "quote": "实际证据文件中的原文片段"}]
}
```

| `kind` | 来源要求 |
| --- | --- |
| `post_fact` | 证据必须来自**同帖**登记的 `post` / 明示合成的 `synthetic_post`；`quote` 必须逐字出现在所指文件中 |
| `product_fact` | 证据必须来自**同帖**登记的 `product`；不能借用原帖作者的话、人物设定或假想购买经历证明产品能力 |
| `fictional_experience` | 可选记录；`evidence` 填 `[]`，属于培训人物的购买/持有/使用/关系/感受，不需要真实用户来源 |

有产品能力/限制、实际原帖细节等可核验断言时必须逐项登记；不必把每句口语拆成记录。一个片段同时涉及原帖与产品事实时，按不同事实分开记录并各自给出依据。记录只证明“这条正文声明使用这些原文”，无法证明原文真实、语义支持充分或所有事实均已覆盖。不得把客观产品参数伪装成 `fictional_experience` 逃避产品核验。

## 绑定与检查

在state所在目录运行以下标准库命令，按实际文件名替换 `state.json`。`<技能目录>`替换为本次实际读取的`SKILL.md`所在目录的绝对路径，保留引号：

```bash
python3 -c 'import hashlib,json,pathlib; p=pathlib.Path("state.json"); s=json.loads(p.read_text()); s["draft_sha256"]=hashlib.sha256((p.parent/s["draft"]).read_bytes()).hexdigest(); p.write_text(json.dumps(s,ensure_ascii=False,indent=2)+"\n")'
python3 "<技能目录>/scripts/check_training_comments.py" state.json --profile cw5 --json
```

数量检查配置如下，二者使用相同state结构、编号解析、父句、人物、来源、事实断言及hash检查：

- `--profile legacy`：每帖2–4条主评，每组0–4条回复。省略 `--profile` 仍默认采用legacy，保持旧稿与原调用行为；不按日期、目录或正文数量自动猜配置。
- `--profile cw5`：每帖2–4条主评，每组最多8条回复，每帖至少1组达到5条回复。机器不限制最多2个长讨论组；通常选择1–2组、主评以3–4条为主以及讨论的产品相关性由语义审稿判断。不能把数量通过当作主评选材或讨论质量通过。

Python调用分别为 `check_state(state_path)` / `check_state(state_path, profile="legacy")` 与 `check_state(state_path, profile="cw5")`，均返回错误数组。重查CW5稿须继续显式使用cw5；不把旧稿改按新配置检查以重写历史结论，也不把新稿结构失败静默降级成legacy。

`--json` 输出机器可读报告，其中 `profile` 记录实际采用的配置；批次应连同命令或调用配置保存报告。退出码0仅表示本次培训草稿结构检查通过，1表示存在列出的结构问题；未知CLI配置由参数解析拒绝。报告始终声明 `semantic_review_required: true`。非 `training_fiction` 模式直接失败；本检查器不能替代真实消费者模式的旧检查或将其冒认通过。
