# 跨产品评论写手能力库

版本：`2026-09-15-CW5.4.2`。所有项目共用此处的写法；产品资料只补型号、能力与命名。读懂材料与任务，找到消费者会产生兴趣的部分，再选择说法。横测培训以任务指定的目标产品为种草中心，比较是素材，不把评论写成中立导购。复杂表达不优先，简短表达也不自动更好

## 用途与材料

写作、改写、案例演示统一为`training_fiction`，交付顶部只标一次“培训用假想消费者草稿”，正文正常使用消费者口吻。允许假想购买、持有、使用时长、生活关系、场景与主观感受；人物存在`personas`，不写成用户本人经历或真实消费者反馈。真实链接、素材或用户说用过均不切换模式

原帖事实、产品事实与假想人物分开。假想亲测不能证明功能、参数、兼容、量化效果、普遍性能或原片设置；主观喜欢不自动证明效果全由设备造成。仅明确核验真实亲历、真实材料或复核旧稿时进入原产品审查流程，保留旧稿模式。本技能不用于实际生产、发布或账号操作

需要读取社交平台链接时，由宿主环境提供正文、字幕、评论和媒体证据；有批量读取工具时先按其规定一次提交完整链接集，本技能只消费返回的证据。没有读取能力时只使用用户提供的材料，不能把搜索摘要、抽帧或推测写成完整视频事实。充分用户材料可直接用；没有原帖的合成命题须明示，不能冒充已采集帖子或热评。涉及讲解、声音、笑点或完整叙事时须有相应材料，抽帧不能代替未听到的对白。问题链接、缺失材料和不完整证据需保留范围并交由宿主处理，不以补读或猜测填空

## 读取与选材

写稿或改稿时读[表达参考](references/writing-reference.md)；需要识别细类时读[帖子类型选材](references/post-type-selection.md)，它保留用户分类资料的出处。按[产品路由](references/product-routing.md)只取当前产品知识，不回调完整旧写作流程。已读资料不循环加载，无专属技能的产品也可用充分商品资料与官方来源

补充体验语料、完整讨论、使用阶段或逐句反馈时，按[体验材料收录](references/experience-materials.md)保留原话与上下文，沿用帖子类型分类。材料可以完整，评论只取最值得说的一点；优先补强方向不限定品线卖点，真实短讨论不改变当前新稿展开与交付要求。

遇到两台或以上产品的同场景实拍、成片对照、排名横测或使用后取舍时，进入[横测选材说明](references/cw5.4/comparison-calibration.md)。先确认原帖真的在比较结果、过程或选择，不能只因出现多个产品名就触发。普通“帮我选哪个”但没有实际对照证据的帖子，仍按提问或选购处理。横测只改变选材顺序，不改变培训模式、数量、格式或产品专属边界。

内部简记：整帖在讲什么、产品是什么角色、最值得喜欢什么、怎样说最顺。分类帮助检索，不规定“旅行写便携、开箱写想买”；不从某一帧的小物件另编支线，正文无需复述视频

先区分已发布单帖与达人主页／新品预写。已发布内容先理解整帖；主页预写结合任务目标产品的吸引力与实际取得的往期作品、评论材料选择需求，不凭昵称或分类猜达人风格，不把尚未发布的新帖写成已看见。此类任务按[2026-09-15学习经验](references/calibration-20260915/learning.md)处理，原始反馈与[白色Pocket4P批次边界](references/calibration-20260915/batch-boundaries.md)单独保存，不将一次数量、禁提或交付布局改成默认

新品的假想预订、赠送与试用兴趣仍可写，人物经历应符合新品时间，不能写使用该新款多年。审美喜欢不补出材质、涂层、触感或性能事实；假想预订不证明真实库存、售价和交期。产品知识支撑想说的关注，不按功能逐项分派人物，也不先编生活故事再塞产品名

横测另记：参与比较的产品、实际比较轴、原帖结论和证据强度，并明确本任务的目标产品。先判断整帖是在测画面、测操作流程、比较后期负担还是做购买取舍，再从横测里找目标产品值得被喜欢、被了解或被拿来尝试的那一点。不同主评可以分别关注目标产品的画面偏好、场景适配、使用顺手、拍后处理、旧机升级或一个仍待确认的问题，不要求提到所有产品，也不逐项转述参数。竞品只在解释目标产品取舍时出现，不能让中立的“各有优点看需求”占据主评，也不能单独夸竞品把种草方向带走。

每条主评分别成立产品兴趣。产品明确且展示了相关效果时，直接喜欢画质、色彩、气色等可以独立成稿，不强加型号、经历、追问或购买结论。无关泛夸、重复赞叹不能充数。由整帖联想到自己的相关场景也成立，不要求原帖出现同一地点、人物或动作；设备未确认时不能把任务产品认作原片设备，仍可写有整帖来由的使用期待、本人假想感受或偏爱，事实另核验

不同消费者从熟悉度、当前处境、偏爱与语气上区分，同一身份不绑定一种句式。感受说清就可停，有作用的长句保留；不强制完整消费故事、小缺点、反转、亲友背景或口头禅。重复时先换真正想说的事，再改措辞

同一卖点可因适用范围、使用需求、实际操作等不同关注产生合理表达，按[句义与术语详略](references/writing-reference.md#同一卖点按句义选择详略)判断。准确功能名可以重复，不以换大小写、近义词或删条件制造差异；条件影响本句理解时保留，仅表达兴趣时可简写，但不改变能力范围。不设不同写法的比例，已自然成立的原句保留，只调整关注点或句式扎堆的部分

## 主评、回复与格式

- 每帖通常3–4条主评，确实只有两个成立角度时减为2条并在教学记录说明；不拆同一个意思凑数
- 每帖选1–2条主评各展开5–8条产品讨论，其余各0–4条回复。主评先独立成立，回复者再接感受、偏好或问题；可多人分别回应、接较早回复、原评论者再次发言，不预设角色顺序或完整问答
- 展开楼可有短问、调侃、普通附和。讨论价值看整楼，不要求人人新增卖点；不靠连续认同、重复解释、共同设计拍摄方案或统一下单凑数。没有设置、套餐或实拍答案时保留缺口，不代编博主答复
- 场景问题重点问自己的使用期待。确有使用或理解需要才索取参数、原片或教程，有更新线索才等后续，不把追问博主当默认网感
- 横测主评优先表达对目标产品的消费者立场：直接喜欢目标产品呈现的效果、联想到自己的场景、分享用后取舍、对目标产品的操作或外观心动，或保留一个与目标产品有关的具体疑问。允许一条很短的反应、一条中等长度的联想和一条较完整的态度同时出现，也可以全是短句或只留一条长句，不设顺序或比例。回复继续围绕目标产品的偏好、习惯、场景和信息缺口展开，可以有不同意见，但不要把竞品卖点轮流讲成等量推荐，不统一下单、不为凑楼层制造冲突。原帖若没有证据显示目标产品在该轴胜出，改写成个人偏爱、适配期待或待核问题，不能编造目标产品全面更好
- 对外为编号主评＋单层四空格缩进回复，每帖从1编号，每条评论正文一行，不显示A/B标签、分析或来源。教学说明另页；内部记录实际说话者和直接父句
- 产品英文名与型号内部连写，正文不用中文句号或句末英文句点，编号点、小数和有效链接的点除外。同帖实际点名时自然变换准确称呼，不编简称、不设点名比例；`Osmo`只在Pocket正文禁用

讨论或关联不足时从已有材料重新选材，缺证按上方问题交人工规则处理；仍不足须标明教学交付未完成，不能删成零回复后算完整。用户当次明确数量优先；超出检查器支持范围如实说明，不伪造通过

## 检查与交付

用[现有state模板](assets/training-state.template.json)及[检查契约](references/training-contract.md)绑定唯一最终编号稿、SHA256、来源、人物、父句和事实断言，新稿显式运行：

```sh
python3 "<本次技能目录>/scripts/check_training_comments.py" training-state.json --profile cw5 --json
```

机器检查2–4条主评、每楼最多8回复、每帖至少一楼达到5条；通常展开1–2楼及两主评减量理由由内容审稿判断。第5–8回复同样检查人物、父句、事实和来源。state与接口不变；省略profile仍为旧数量规则，仅供兼容，不用于新稿绕过展开要求

审稿先看原帖和正文，再看创作说明，分别判断整体理解、每条产品兴趣与自然程度，逐条读到最后回复。先逐链接比较主评与回复的声音、篇幅，再看跨帖关注、句式与对话走向；长度仅作线索，不设字数比例、标点配额或机器自然度分。保留自然长句，减少反复的背景＋用途＋价值总结及无用三连列举，不按逗号数判失败

修改定位到原句，保留已经成立的表达；新旧比较先乱序读正文，允许原句更好。教学说明简记整体、选材取舍、回复关系和删改理由，不能为生硬正文辩护。适用时独立审稿；结构通过不证明自然或获得用户认可

审稿区分术语重复与意思重复、明确禁提与减少重复的反馈；不把“少提”执行为全删，也不统一加回条件或替换成新句式。主评与回复一起判断，需要变化时先确认每句话想说什么

## 校准与接续

风格纠偏与认可范围见[压缩反馈](references/feedback.md)。教学按需看[直接表达对照](references/cw5.3/expression-calibration.md)及[学习经验](references/calibration-20260915/learning.md)，不加载旧版本全套过程。历史案例只供回顾或格式兼容检查，不进入日常写手学习或新验收输入。所有新候选待用户校准，明确认可后才收入认可案例；案例不能换产品名直接套用

后续获授权的共用反馈只维护这一份，保留单句、整批与产品专属作用范围。旧稿和旧报告若由宿主另行提供，仅作复盘参考，不恢复已被替代的规则
