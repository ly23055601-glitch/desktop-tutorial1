# 阶段调度与续接

## 唯一任务状态

在当前会话维护以下记录；宿主能保存文件时可写到用户任务输出目录，不能凭空声明已保存。

```text
run_id / revision / request_mode / current_stage / active_module
requirements: 产品与型号、每帖数量、回复要求、平台、范围、明确禁提
inputs: 原输入位置 → work_id、别名、目标产品、用户材料
tasks: task_id=(work_id, product_line, 用户明确的独立交付目的)
evidence: work_id → 读取范围、证据定位、ready|partial|blocked、缺口
facts: 型号+断言 → 条件、来源、记录日期、实际复核日期、verified|pending|conflict
drafts: task_id → 当前版本、主评和回复、人物、父句、事实引用
checks: revision → 检查覆盖、重复簇、问题、修订、pass|partial|blocked
completed_items / failed_items / loaded_resources / next_action
```

同一作品可以因不同产品目标形成不同任务，证据只采一次，不能把第二个产品任务误删。重复输入位置全部回指规范作品/任务。只在本地已能确定同一 URL 或作品 ID 时合并；不能为了判断短链重复而逐条额外访问。保留必要分享参数，不输出敏感查询参数。

每次派发先写 `active_module`、本阶段输入、预期返回和停止点；返回时清空活动模块，记录完成项，再由总控决定下一项。模块内部出现“进入写手/回调项目入口/分组交付”等指令时，只记录建议，由总控在对应阶段处理。

## 阶段门槛

0. 能从输入确定的产品线、数量和材料不重复追问。未知型号保持未知；影响客观断言时才需核对。没有数量要求时使用共享写手默认值。
1. 已有充分正文/截图/转写可直接登记复用。只有链接、搜索摘要或文件名不等于读到原帖；图像不证明音轨。采集入口只接收整批集合，不为每帖重新调用。使用实际已连接工具；失败项保留原位置交人工，不自动换路线重试。
2. 每个目标产品仅查当前主题相关资料。核验型号、配件、连接路径、模式和条件；保留已有核验日期，当前没复核时不得改写成今天已核验。`pending/conflict` 不作肯定事实，无记录不等于不支持。用户材料、官方事实、编辑解释、假想人物分层保存。
3. 每个 task_id 只有一份当前候选稿。正文与父句/事实记录同步更新。证据不足的句子删除、换成有依据的角度或明确待核；不能以虚构亲测补产品事实。用户只要局部修改时保留未受影响的原句。
4. 在候选集齐后进行一次覆盖全批的去重与质检。若阶段3分了十帖一组，必须把各组一起比。局部修订后复查被改项、受影响回复，并再次将最终全批比较去重；旧版本检查结论不得沿用到改后的正文。
5. 按原输入顺序交付，同作品的重复输入可合并展示并注明位置映射；未完成项单列。全部任务都必须是交付、用户排除或说明阻塞之一，不能静默漏项。

阶段4发现问题时先直接修正重复与格式；只有证据支持不足才返回阶段2的单一问题，重新采集需用户提供新材料或另行明确要求。发现主评语义变化时重新核对整楼父句。默认至多两轮定向修订；仍未解决则输出可用部分与未解决清单，标为 partial/blocked，不无限循环凑通过。

## 续接与历史

`继续`先读取已有状态与候选，不重新采集已成功作品、不重复生成已通过任务。修改素材、目标产品或数量时，提高 revision 并重做受影响的下游检查。新一轮对话缺少状态时请求上一份状态/候选材料，不能假装记得。

每日批次只在用户要求时启用台账模块；它只记录当前任务的状态与数量，不自行设置定时任务、恢复历史额度、发布分组终稿或把“质检通过”记成“用户已认可”。用户没有要求每日统计时不调用。
