# Q：整批去重与最终质检

Q是唯一终审阶段，由总控执行，不新增第21个SKILL。写手仅提交候选和state。先冻结全部最终候选版本，所有主评、回复、品线和分组共同进入检查，不能用单组通过代替整批通过。

## 检查顺序

1. **覆盖**：expected_link_ids 与最终候选一一对应；重复输入保留别名，不重复创作；缺失/跳过逐项有原因。只完成一部分时整体为partial。
2. **事实**：逐句核对原帖事实、产品型号/条件/来源/核验日期、人物假想经历；pending/conflict不作肯定断言；假想人物不能为产品事实作证；审查旧稿保留原材料性质。
3. **全局去重**：比较同帖主评、同楼回复、主评与回复、跨帖、跨组、跨品线。区分全文相同、换词但意思相同、相同开头/句式/人物故事、相同问答走向。优先保留最贴合该帖、依据最足、最自然的一条，其他定点换真实关注角度或删冗余；不能只换产品名、大小写、近义词，也不能为去重删掉必要条件。
4. **合理重复**：准确型号/术语、短附和不直接判失败。同一卖点对应不同需求、操作或适用条件可以并存。相似度脚本仅列候选，必须读上下文后裁定，保留项写具体理由。
5. **质量与格式**：是否读懂整帖、每条是否独立有意义、人物和回复父句是否连贯、是否模板腔/硬塞参数、数量和版式是否符合本次任务、模型名是否准确。不能把“少提”当“禁提”，不能按字数或自然度分数代替阅读。
6. **绑定**：训练新稿运行CW5结构检查及批次扫描；正文、state或证据变动后旧检查失效。质检结论绑定本轮稿件、state、来源文件指纹，再交付。

## 有Python时

每个 link_id 对应一份 draft.md（一个 `## 1｜…` 章节）及 training state。state 的 id/product_line 与批次项匹配。先按 [批次模板](../../../examples/batch.template.json) 填写 `batch.json`，运行仓库根目录命令：

```bash
python scripts/check_batch_quality.py path/to/batch.json --output path/to/quality-report.json
```

初次 `semantic_review.status=pending` 正常，机器结构通过也不能标终审通过。根据报告逐一审查 duplicate_candidates 并完成事实/语义审稿，把实际结果填入 semantic_review：status、reviewer、notes、reviewed_fingerprints 及 candidate_decisions。每个候选必须有 `keep_distinct` 或 `allowed_repeat` 裁定及具体理由；需要修改的候选先返工并重新扫描，不以填“解决”绕过真实重复。

再运行同一命令验证指纹与裁定覆盖。脚本只检查结构、文本相似候选及审查记录，不能证明来源真实或语义审稿正确；`passed_recorded_review` 表示机器检查通过且已有匹配当前内容的审稿记录。

review_existing 只做通用文本预检、定位与去重候选，返回 `review_only`，不应用CW5数量/虚构标识要求。旧稿的事实审查结果由Q单列，不能说已通过training checker。用户指定超出CW5的数量/格式时也单列 custom_contract 的人工审查结果和机器不适用项，不为机器通过改掉用户要求。

## 无Python时

按上述六项逐条审核，用“帖ID/主评或回复ID/问题/修改或保留理由”记录。明确“已完成内容复核；机器检查未运行”。若完整稿件不在可读范围，列未核范围并标partial，不声称跨组去重完成。

## 最终交付

交付当前编号稿及简短报告：输入数、实际完成/缺失数、重复输入处理、主评/回复总数、去重删改/合理保留、事实待核项、机器检查状态、内容复核结论。培训稿顶部标识一次；教学诊断放正文之外。只有全部项覆盖、没有未解决问题且内容复核完成才称整批完成。保留task_id与revision供接续，不把本次通过当永久认可范文。
