# DJI Mic 批量评论低同质化

本参考用于 4 个以上链接、跨批续写或用户明确要求进一步去 AI。目标是去掉固定生产骨架，同时保留真实锚点与 Mic 产品关联。阈值是复核护栏，不是新的文案配额。实时采集必须先遵循 [统一读取 Skill](../../read-social-links-with-social-helper/MODULE.md)，本参考只处理完成后的证据包与文案。

## 证据卡与滚动账本

先为每个链接建立证据卡，再决定表达方式。不得先写三种模板，最后找画面补进去。

证据卡最小字段：

~~~text
原序号｜平台｜作品ID/规范链接｜可读状态｜确认型号
锚点ID（画面/声音/动作/原话/测试结果）｜声音证据条件｜事实边界｜媒体路径
证据等级｜用户缺口｜产品机制｜可感收益｜购买阻力｜可达S级
~~~

滚动账本保留最近约 30 个链接或 150 条主评的摘要与指纹：

~~~text
锚点ID｜关注任务｜语气卡｜开头类型/前6字｜句长档｜标点签名
产品称呼/位置｜回复数｜互动路径｜梗结构｜文本指纹
种草机制｜证据等级｜实际S级
~~~

只保存分类、计数、指纹和必要路径，不把旧评论全文、原始抓取输出或 op 长对话持续塞回上下文。

## 生成前分配

每 6–10 个链接做一次轻量互斥分配，不使用固定顺序：

- 关注任务：即时反应、纯偏爱、佩戴顾虑、连接疑问、收音条件、套装识别、技术核验、合理反方。
- 种草机制：需求唤醒、结果想象、产品归因、阻力化解、选择缩窄、升级判断、合理反方。
- 开头类型：具体物件、动作、原话、声音变化、真问题、偏爱、轻反驳、产品动作。
- 语气只约束关注点和信息密度，不写成“学生党、老师、探店博主”等虚构人设。
- 相邻链接不复用同一套“开头＋关注任务＋产品位置＋互动路径”。
- 三条主评不固定为“情绪—生活—技术”，也不强行短中长各一条。
- 产品证据不足时保持低等级，不为轮换补造功能。

并行起草前，主任务给每块 2–3 个禁用组合，并共享最近账本摘要。各块不共享大段旧成品。

## 主评护栏

- 每条只抓一个瞬间、一个声音变化或一个操作结果。必要对照最多两个对象。
- 两个以上顿号构成三项枚举、`先…再…最后…`、或四个以上连续短逗号分句时，检查是否在“看图报菜名”。原帖本身是套装清单、音色列表或受控多档对比时可保留，但只作为人工复核例外。
- 禁止“画面复述 → 功能解释 → 价值升华”。留下最值得反应、最想问或最有分歧的一层。
- 去掉产品词和标点后的前 6 字跨至少 3 个链接出现第 3 次，优先重写最新一条。
- `这段/那一下/最后`、`我第一反应/我反而/偏偏` 等观察壳同一链接最多一条；跨批过密时换关注任务，不只换同义词。
- 三条的句长、开头和结尾形式需要自然差异，但不要按字数配额机械凑档。
- 总结腔禁用：`本质上、这说明、这才是、产品价值、核心优势、适合谁、说到底、所以说、逻辑很顺、工作流闭环`。
- “角色：台词”“嘴上…手上…”“这哪是…分明是…”等人工造梗同一链接最多一次，且拿掉梗后仍需保留独有锚点。

## 产品露出护栏

- 默认“两明一隐”只作建议。完整精确型号通常每链接最多一次，同一简称不要固定在同一组或句首。
- 三条都需与 Mic 硬件、录音动作、收音结果或真实产品问题关联；隐性组不能退化成普通生活热评。
- 同一组主评与回复反复出现同一个完整型号时复核；型号纠错或多代对比可保留并记录理由。
- 产品词长期位于前 6 个字符、长期固定第 1/2 组或连续多个链接使用同一称呼时，调整位置与句法。
- 删除产品名后可以原样套到任意开箱、唱歌、校园或旅行内容，直接重写。

## 楼中楼反排演

- 默认两条回复。`2/2/2` 完全允许，不因“整齐”单独判错；抖音整批以两条为主也正常。
- 第三、第四条必须对应真实分歧、纠错或自然岔题。批次中三条以上回复组占比明显偏高时复核，但不设必须达到的数量配额。
- 禁止固定链路：

  - 接梗 → 再接梗 → 总结梗；
  - 什么麦/哪款 → 报完整型号 → 懂了/种草/下单；
  - 认同 → 科普 → 反驳 → 条件式成交；
  - 单人需求 → 双人需求 → 套装结论；
  - 三条回复分别补完测试变量、设置和最终建议。

- 最后一条以“对、所以、这才、确实、说到底、重点是”开头并总结前文时，优先删除或改成旁枝。
- 不使用“××党、××派、路过、集合、先来、出现”等标签给回复者分配角色。
- 一条可以只接情绪，另一条补条件或不同意；允许话题停在问题，不需要每组形成共识。
- 三组拥有完全相同的“短接梗＋技术条件”骨架时，至少换一组的入口，而不是只调字数。

## 重复与基线

按以下顺序处理：

1. 完全相同的主评：硬错误。
2. 只替换型号、品牌、数字、标点或表情后相同：硬错误。
3. 当前批主评骨架高度相似：警告，复核关注任务与信息顺序。
4. 与历史基线完全或高度相似：优先重写当前新稿；历史稿本身不参与当前结构错误和退出码。
5. 短回复如“哈哈、同问、确实”可自然重复，但同一组不能重复，批次中过密仍提示。

近重复命中后按顺序改：

1. 换关注任务或立场；
2. 换锚点入口和信息顺序；
3. 换句长、停顿与结尾；
4. 换产品称呼和位置；
5. 换楼中楼入口或直接删除不必要的第三条。

只换同义词不算去同质化。任何改写不得丢失真实锚点或补造声音表现。

## 检查器

运行：

~~~bash
python3 <skill目录>/scripts/check_comment_homogeneity.py draft.md
python3 <skill目录>/scripts/check_comment_homogeneity.py draft.md --baseline recent.md
python3 <skill目录>/scripts/check_comment_homogeneity.py draft.md --format json
~~~

`<skill目录>` 指向包含本技能 `MODULE.md` 的绝对目录；不要依赖任务当前工作目录。

检查器兼容两套纯净稿：

- `## 1｜URL` + `主评论：` + `↳ 回复1：`；
- `## 1. 作品ID` + `1. 主评` + 纯 `↳ 回复`。

重点诊断：

- 章节、三组主评和 2–4 条回复结构；
- 精确、规范化和近似重复；
- 三项枚举与固定作文句式；
- 多层回复过密、最后一条总结、三人配合演戏；
- 虚构身份标签与未经支持的购买/使用证言；
- 同组产品名称复读、固定产品位置和产品关联不足；
- 与 `--baseline` 的跨批重复。

结构错误以及当前批主评论的完全／规范化重复属于错误。身份、购买或使用经历只能由链接证据和用户输入判定真伪，因此检查器只作复核警告；其他风格代理也通常只给警告。`--strict` 可让警告返回失败，但仍需语义复核，不能为追求零警告把真人表达改成新模板。

## 快速批量流程

1. 复用统一读取 Skill 的原序号、逐链接状态和证据包；不得自行定义批次、链接规范化、补抓或重试。
2. 成功项压成证据卡，失败项单列；成功项不等失败项。
3. 6–10 条一块起草，各块读取共享账本摘要和本块禁用组合。
4. 合并后运行当前批与历史基线检查，只重写命中组。
5. 在批次目录写 `mic_comment_state.json`，记录证据、游标、分块、QA、警告例外和未解决项。
6. 交付时保留链接顺序和失败状态，不输出内部标签、账本或心理机制。
