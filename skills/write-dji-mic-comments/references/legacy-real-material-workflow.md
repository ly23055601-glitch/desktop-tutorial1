# DJI Mic 真人评论

为每个链接起草与实际内容绑定、产品关联自然、低 AI 痕迹的中文评论。目标是像观众被某一个画面、声音、动作或问题勾住后顺手留言，不复述全片，不把产品名贴到万能热评上。

当前规则版本：`2026-09-02-MIC-SYNC1`。

## 不可改变的边界

- 本技能始终属于 DJI Mic 项目，只处理 DJI Mic 系列及原帖自然涉及的竞品收音设备。不得迁移成相机、云台或泛 DJI 评论技能。
- `op` 项目只提供可迁移的写作反馈和流程经验。不得带入其产品型号、参数、卖点、画面、旧评论、账号状态、媒体路径或发布权限。
- 优先级固定为：当前用户要求 > 当前链接证据 > 当日官方 DJI Mic 事实 > 本技能固化规则 > op 的可迁移风格增量 > 平台常见语态。
- 本技能只起草，不发布、点赞、关注、收藏、私信或操作社交账号。

## 快速路由

- 普通 1–3 个链接：读取本文件、当前链接证据和 [references/product-seeding.md](../references/product-seeding.md)。
- 4 个以上链接、跨批续写或用户要求进一步去 AI：再读取 [references/low-homogeneity.md](../references/low-homogeneity.md)，使用检查器和批次状态文件。
- 涉及型号、参数、兼容、套装、价格、竞品或功能结论：读取 [references/product-knowledge.md](../references/product-knowledge.md)，并以执行当日官方来源核验。
- 用户明确要求“从 op 同步／更新 Skill”时，读取 [references/op-style-sync.md](../references/op-style-sync.md)，按其中协议更新固化基线。普通写稿只使用已固化基线，不每次回读 op 长对话。

## op 对话同步

本次已将 op 中稳定且可迁移的规则固化到本技能。以后只有用户明确要求重新同步，或指出某项 op 新反馈也应成为 Mic 长期规则时，才读取 op 最近相关对话。

同步时只提取：

- 用户明确指出的好坏、修改要求和验收标准；
- 证据压缩、写作协作和 QA 方法；采集速度、批次与问题交人工规则不得从 op 同步，统一由全局读取 Skill 管理；
- 句长、开头、停顿、产品露出、互动路径及已确认的禁用模式。

不得把助手自称“已优化”当成用户认可，也不得把某条成品直接当模板。详细白名单、黑名单、冲突处理和增量记录规则见 [references/op-style-sync.md](../references/op-style-sync.md)。

## 先取证，再写

1. 识别实际承载平台、规范链接或作品 ID、作者正文、标题、标签、可见评论语境和精确 Mic 型号。
2. 每个链接提取 1–3 个有效锚点：一个画面、动作、原话、声音变化、设置步骤、测试结果或评论区真实争议。短内容只有一个有效锚点时可换观察任务，不得补造第二、第三个画面。
3. 为每个链接压成证据胶囊：

   `原序号｜平台｜作品ID/规范链接｜可读状态｜确认型号｜1–3个锚点｜声音证据条件｜证据等级｜用户缺口｜产品机制｜可感收益｜购买阻力｜可达S级｜事实限制｜媒体路径`

4. 音质、降噪、风噪、爆音、内录或抗干扰是核心时，必须实际确认对应片段及测试条件。只看标题、封面或画面不能推出声音结论。
5. 只根据可见、可听、可转录或用户明确提供的内容写作。用户提供的描述可作为输入证据，但未独立核验的型号或参数不得伪装成已核验事实。

### 社媒助手批量读取

- 需要从抖音、小红书或 B站链接读取或采集内容时，先完整读取并遵循 [统一读取 Skill](../../read-social-links-with-social-helper/MODULE.md)。它是 Chrome、社媒助手、分平台批次、小红书节流、字段、评论深度、问题交人工、导出下载、账本及一次证据验收的唯一规则源；本技能和 references 中的旧采集描述均不得覆盖它。
- 一次性交给统一读取 Skill 当前请求中这些平台的完整待读取链接集合，并保留原序号；由它统一去重、分平台、分批和处理失败项。不得为了逐链接锚点、证据胶囊或写作分工而拆成多次单链接调用；逐链接分析只消费其返回的证据包。
- 本技能只消费统一证据包并追加 Mic 所需的声音片段、测试条件、型号确认与事实限制。成功项先进入写作，失败项保留原序号；不得拿相似作品替代。
- 用户已经提供足够材料并明确无需实时读取时，可直接使用其导出、截图、录屏、字幕或正文；不得将普通网页搜索或其他来源冒充成社媒助手结果。

连接、登录、验证码及控制故障依统一读取 Skill 直接交人工，保留原序号、已有证据及缺口，不以补读重采失败作品；不得静默生成通用评论冒充已读。其他平台按全局规则登记完整集合、批量组织，以已连接外部 Chrome 单次读取原页可见内容，问题项同样交人工。

## DJI Mic 事实与命名

- 精确区分 DJI Mic Mini、DJI Mic Mini 2、DJI Mic Mini 2S、DJI Mic 2、DJI Mic 3 及原帖出现的其他型号。不能从画面、正文或作者表述确认时，用中性称呼，或在该判断会改变成稿时请用户补充。
- 数字参数、兼容、价格、套装、发射器数量、声道、续航、传输距离和竞品事实均具有时效性，执行当日以品牌官方产品页、规格页、兼容列表或支持页核验。
- 传输距离保留空旷、无遮挡、无干扰等测试条件；32-bit 浮点内录不能写成所有爆音都能恢复；降噪、音质和抗干扰不能从参数表直接宣布绝对胜负。
- 平台发布的声音可能经过压缩、剪辑、配乐、混响、降噪或响度处理。没有受控同场景对比或原始音频时，只描述“这条里听到什么”，不外推产品普遍表现。
- 在指代清楚时混用精确型号、`大疆 Mic`、`Mic Mini`、`Mini 这款`、`这个麦`、`这颗小方块`、`发射器`、`接收器`、`充电盒` 等称呼。同帖有多个型号时优先准确，不用昵称制造歧义。
- `大疆 Mini` 容易和无人机混淆，不单独使用；裸 `Mic` 也不作为清楚的产品称呼。

## 写三组真人评论

默认每个可读链接交付 3 组，每组 1 条主评论和 2–4 条楼中楼。

### 三组都与 Mic 有关，但不靠复读名字

- 三条主评论都必须与可见 Mic、录音动作、收音任务或真实产品问题有关。默认“两明一隐”：两条自然出现产品称呼，一条通过佩戴、发射器、接收端、充电盒、连接或声音任务隐性关联。
- “两明一隐”是建议，不是硬配额。完整精确型号通常每链接最多出现一次；原帖明确比较多个型号时，为避免歧义可以分别点名。
- 删除产品名后如果仍能原样套到普通开箱、唱歌、旅行或校园视频，说明产品是后贴的，必须重新绑定 Mic 动作、录音结果或购前问题。
- 每组只讨论一个产品点。产品关联强度来自“锚点 → 录音结果 → 用户收益或条件”，不是增加名称密度。

### 一条只抓一个瞬间

- 每条主评论只抓一个动作、物件、台词、声音变化或测试结果。必要对照最多并列两个对象。
- 禁止连续盘点三个画面、物件、动作或功能，禁止“复述画面 → 解释功能 → 总结价值”的作文闭环。原帖本身是清单或受控多档对比时可以例外，但仍只评论其中一个最值得讨论的结果。
- 三条不要固定成“短反应＋生活代入＋产品提问”。从碎片反应、偏爱、真问题、轻吐槽、轻反驳或未说完的判断中按内容选择；长短、开头和标点自然不齐。
- 允许半句话、停顿和普通附和。删掉“这才是、本质上、说明了、产品价值、适合谁、逻辑很顺、工作流闭环”等总结腔。

### 楼中楼像临时接话

- 默认以 2 条回复为主。抖音整批都只有 2 条是允许的，不得为了“变化”机械分配 `2/3/4`。
- 只有原内容真的形成分歧、技术纠错或话题岔开时才保留第 3、4 条；最后一条不得负责概括前文或替产品收口。
- 禁止“接梗 → 再接梗 → 总结梗”“提问型号 → 报完整型号 → 集体种草”“认同 → 科普 → 反驳 → 条件式成交”等排练式链路。
- 不用“学生党、探店党、参数党、战损党、××党路过”分配角色，也不凭空自报老师、博主、店主、家长等身份。视角通过关注点体现，不写成账号传记。
- 允许回复只接一个情绪、直接不同意、补一个条件、跑偏半步或聊到一半停。不要让所有回复共同完成一份购买决策树。

### 平衡种草

- 先按证据等级确定可说到哪，再选择需求唤醒、结果想象、产品归因、阻力化解、条件式选择或合理反方。详细等级和 Mic 收音收益翻译见 [references/product-seeding.md](../references/product-seeding.md)。
- 每个证据充分的链接至少有一组把产品点翻译成可感收益；允许另一组只表达情绪、疑问或不同意见，不要求三组集体销售。
- 每链接最多一组使用克制购买倾向，如“经常拍这种场景会多看一眼”。不写“闭眼入、必买、无脑冲、吊打、智商税”，不制造虚假稀缺或群体压力。
- 竞品只在原帖、评论区或用户任务自然涉及时比较，写清具体型号、场景、依据和失效边界。无法核实时改成真实问题，不替品牌补答案。

## 平台语态

- 小红书：生活细节、佩戴存在感、上手阻力和购买顾虑更重要；语气可细腻，但不能写成一篇笔记。
- 抖音：先命中一眼可见或可听的瞬间，句子更短，轻梗最多留一处；回复通常两条就停。
- B站：可讨论设置、连接、声道、测试变量和型号纠错，但不要把三个回复排成完整实验报告或决策树。
- 微博：先给明确观点，再留一个可讨论条件；不虚构热搜、公众共识或销量。

用户指定目标平台时，指定优先于来源平台。跨平台改写必须重新选择钩子、句长和互动入口，不能只替换几个口头词。

## 批量低同质化与状态

- 4 个以上链接建立滚动账本；多于 8 个可读链接时按 6–10 条分块。主任务先分配不同的关注任务、开头、句长、产品位置、互动路径和种草机制，各块只共享摘要与禁用组合。
- 抓取完成后只携带证据胶囊，不反复加载长对话、原始导出和旧评论全文。历史成品只作为跨批相似度基线，不作为正面模板。
- 在批次工作目录根据 [assets/mic_comment_state.template.json](../assets/mic_comment_state.template.json) 创建 `mic_comment_state.json`。只记录规则版本、证据路径、成功/失败序号、op 同步游标、账本摘要、输出路径、QA 与未解决项；禁止保存账号、Cookie、Token 或密码。
- 草稿完成后，以本 `MODULE.md` 所在目录为基准运行 `python3 <skill目录>/scripts/check_comment_homogeneity.py <draft.md>`；跨批续写时加 `--baseline <recent-output.md>`。不得假定当前工作目录就是技能目录。错误必须修复，警告需结合真实证据复核，只局部重写命中组。

## 输出前自检

- 每条主评论能否指回一个具体画面、声音、台词、动作或讨论？是否出现三连盘点？
- 三条是否都与 DJI Mic 的可见硬件、录音任务、结果或真实问题相关，而不是后贴产品名？
- 精确型号是否正确，产品称呼是否混用自然，是否从平台成片越级宣布音质结论？
- 三条是否没有固定槽位、相同开头、相近字数和相同作文骨架？
- 楼中楼是否默认两条就停？保留的第三、第四条是否真有分歧或旁枝，并且没有总结收口？
- 是否出现“××党／路过”、虚构职业关系、购买持有、使用时长、亲测、朋友在用或已下单？
- 回复是否像多个人临时接话，而不是品牌安排的问答、群体夸赞或三人配合演戏？
- 产品收益是否受证据等级约束，每组是否只谈一个点，竞品和参数是否来自当日官方来源？
- 批量任务是否保留原序号、隔离失败项、避免跨链接混锚点，并完成当前批与历史基线检查？
- 最终是否只输出用户要求的成稿，没有发布或账号操作？

任一硬项不满足，先重写再交付。
