# Pocket4 / Pocket4P 详细场景选材

本目录有 22 张可独立检索的具体场景卡，均为 `editorial_hypothesis`。它们把已核产品能力放进一种可能的时间、地点和动作流程，帮助理解能力何时有用、会增加什么步骤、什么时候不适合；不是 22 个真实用户案例，也不是人群调研。编辑日期：2026-09-07。

事实依据来自 [产品事实](../products/facts.jsonl)，原有主题入口保留在 [场景关联卡](../scenarios/cards.jsonl)。这批没有新增社媒采集，没有读取留出材料，没有成片实测，也没有编写正式评论。`checked_at` 是场景编辑日期；产品核验日期仍看每条事实，不能被本页日期覆盖。

## 选材方式

先从当前材料或用户问题确认要做的事：人在不在画面里、是否离开机身、是在动还是坐着、主要保留人声还是画面、是否愿意后期。再找最相近的卡，读取完整 `situation`、`friction` 和 `desired_result`；不要只按“旅行”“亲子”标签匹配。

每次只取会改变当前选择的少量能力。阅读 `fact_ids` 对应原事实的型号、来源地区、条件和 `not_infer`，再回看 `model_notes`。双型号卡中的事实集合是两款各自适用条目的并集，不表示每条事实都能用于两款。若卡上有 `selling_point_ids`，用它反查卖点的用户价值解释，再返回产品事实核对；卖点ID不能替代产品证据。

`workflow` 是编辑拟议的使用步骤，整段不等于已完成官方组合验证的教程。菜单动作、配件和模式组合仍以各条事实可支持的部分为限；拍摄机位、动作设计、试录和检查是编辑建议。手势识别、跟随不丢、合焦、传输速度或成片效果均需现场验证，不能由“有功能”直接变成“这段一定成功”。

`opening_reasons` 记录可能值得讨论的关注方向，不是必须填满的评论槽位；`reply_opportunities` 都以父句确实出现相应信息为前提，只说明可以继续解决什么问题，不模拟真实父句或已发生对话。`voice_card_ids` 仅帮助理解提问与取舍机制，尤其不能从 C2 的独立评论补出父句。公共原话、购买和使用经历保持原归属；无直接表达样本的宠物卡如实保留空列表。

需要评论时再经当前项目写手和共享写手生成培训用假想消费者草稿。人物设定另存，不写回这些场景或产品事实；本目录不规定评论数量、模板或配额。

## 容易混用的边界

- Pocket4 的手势2米是手册建议，不是所有固件的硬上限，也不是Pocket4P距离规格。Pocket4 V手势照片倒计时秒数未由本批核定，不套4P的3秒。需要走入画面时，先在可识别画面内开录并确认，再退到画外走入；要保持原构图时不启用智能跟随。
- 机械增稳、只锁焦点的人像对焦、智能跟随与主角跟随分别理解。增加稳定不能消除所有步行上下位移，对焦优先不会带云台。4P的多人跟随数字、变焦条件和GB模式脚注按目标地区与固件复核。
- Pocket4P物理双摄一次只有一颗工作，不能同时保存两个视角；1x与3x的镜头范围不同。D-Log2的1x条件、广角与中焦慢动作上限、两种最近对焦距离分别保留，不能组成所有镜头通用的配置。
- Pocket4可用内置107GB，Pocket4P为103GB。总可用、当前剩余、能存多久、能拍多久是不同问题；Pocket4的内置麦音频备份不能直接继承给4P。
- FrameTap与Mimo不可并连。App美颜和机内美肤是不同功能；遥控监看不是文件导出。常规竖拍最高3K与横持实现4K竖屏也是不同路径。

更多未覆盖主题与自检范围见 [review-notes.md](review-notes.md)。这些限制帮助决定下一步查什么，不把未覆盖解释成产品不支持。
