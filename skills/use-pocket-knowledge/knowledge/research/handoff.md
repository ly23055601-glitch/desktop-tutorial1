# 新研究怎样进入同一个知识库

用户于 2026-09-10 停用本次接入的 Apify 付费采集工具及话题发现入口。已有研究材料保留；后续需要读取三平台链接时，将当前请求完整集合一次性交给[统一社媒读取](../../../read-social-links-with-social-helper/MODULE.md)。本页只说明已有或另行取得的资料如何进入 Pocket 库，不另定采集数量、排序或恢复规则。

| 状态 | 保存什么 | 能怎样调用 |
|---|---|---|
| 候选已发现 | 原链接、作品ID、关键词、时间和筛选依据 | 只是找帖线索，不能算原帖或评论已读 |
| 证据已取得 | 原始导出、逐帖账本、真实ID、原文位置、实际读取范围和父句 | 可做逐条研究，不能直接当产品事实 |
| 研究已分析 | 当批分析、实际选择、表达候选、分歧与未完成项 | 明确case和推断范围；不标用户认可 |
| 正式入库已审读 | 去重后的语料、相关表达/需求/比较卡、必要的官方核验 | 进入统一简报；旧holdout和停止附件不进入学习 |
| 个人快照已刷新 | 动态统计、来源映射、隔离验证和当前包 | 项目外可调用；封装日期不改变事实核验日期 |

Pocket研究使用维护脚本 `scripts/ingest_research_batch.py`：先预览符合研究格式的批次并核对来源，再显式`--apply`。评论按平台＋作品＋评论ID去重，原文变化单独审阅，不能静默覆盖。导出/账本不足时保留在研究层；`--apply`只代表来源记录写入，不等于语义审读、成像实测或官方核验完成。

审读后将相关材料写入同一份 `corpus/comments.jsonl`、`voice/cards.jsonl`、`scenarios/cards.jsonl` 或 `comparisons/cards.jsonl`；不再建一套“热评正式库”复制相同记录。场景推想可与真实需求关联，但不能删除假设标签。网友新产品主张先记待核，官方依据充分后才改 `products/facts.jsonl`。

原每日 500 条热评学习计划随本次付费工具停用而停止，不按旧授权继续执行。已有批次按实际来源审读入库；计划配置、空目录、去重记录或候选数量不算已学习成果，历史记录不自动成为官方事实或认可范文。

历史每日学习测试记录保留，实际完成情况以当批 manifest 与来源为准；本库已经入库的单次研究见[研究目录](README.md)。
