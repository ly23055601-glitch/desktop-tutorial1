## 写作时怎么用

在本项目提供帖子或已有素材，直接说“按项目Pocket标准写，参考Pocket4P知识库”。[现有Pocket写作技能](../../write-dji-pocket-comments/SKILL.md)已接入本库：先理解当前帖，再按型号、场景和开口理由查资料，最后写主评及需要的回复。

知识帮助写手理解具体兴趣；正文不用堆参数，也不套用来源原句。产品事实进入稿件时仍复核当前官方资料。第三方经历保留真实归属，不能冒充说话者本人经历；当前两帖示例也不虚构过去使用经历。

## 按问题检索

从项目根目录运行；也可直接让写作技能完成检索，无需手动运行：

```bash
python3 "<技能目录>/knowledge/scripts/pocket_knowledge.py" search '人物 中焦 收音' --model pocket_4p --platform xiaohongshu
python3 "<技能目录>/knowledge/scripts/pocket_knowledge.py" search '独自出门 架机 跟随' --model pocket_4 --platform xiaohongshu
python3 "<技能目录>/knowledge/scripts/pocket_knowledge.py" search '导出等待 收纳拆装' --model pocket_4p --limit 2
```

默认每类最多3条、排除holdout。结果不覆盖问题时，拆成具体操作继续查；不能把相邻模式的资料拼成完整教程。`pending`仅提示待核，`case`保留为个案，`editorial_hypothesis`不是人群共识。型号筛选也不能反过来证明原片设备。

## 来源与维护

- [官方来源](sources/official.jsonl)保留型号、地区、日期、原文定位；“已核”表示在记录日期核验，价格、套装、兼容及实际使用能力须按当前来源复核。
- [公开语料账本](corpus/README.md)保留原始导出、逐帖状态、字段与父句范围；未读媒体不补成画面或口播。
- [反馈与本人素材](feedback/README.md)只记录有出处的明确内容，不把自评当用户认可。后续补充本人体验时再记录具体型号、场景和原话。
- 表达规律至少有3个独立作品支持；一两篇的观察继续作为个案。新增材料仍走统一社媒读取技能，不自动恢复本轮已停止的队列。

新训练稿使用当前共享契约的`product`来源与`product_fact`断言；只有真实材料专项或旧LH13审查需要claim登记与`product_facts`接口。知识库、真实材料与独立训练人物保持各自归属。

```bash
python3 "<技能目录>/knowledge/scripts/pocket_knowledge.py" audit --format json
python3 knowledge/pocket/scripts/write_coverage_report.py
```

默认审计检查当前库与引用完整性，不要求恢复已取消的规模目标。旧计划保存在[建设记录](BUILD.md)与`corpus/collection-plan.json`，仅供追溯。结构检查通过不替代事实与语言审读。
