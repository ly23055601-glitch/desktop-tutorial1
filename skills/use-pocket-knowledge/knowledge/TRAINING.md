# Pocket4 / Pocket4P 卖点与场景选材

这个入口帮助写手理解“这个人在此刻为什么会关心产品”。产品事实仍来自官方核验；使用价值是编辑解释，场景是待验证假设，已有用户原话是有明确来源的局部表达例证，三者不互相冒充。

## 从当前材料出发

先看帖里实际发生的动作和说话者在意什么，再取少量相关资料。只有参数时不能补成具体画面，作者尚未开拍时不能评价他已经拍出的效果；训练角色的独立设定按共享写手处理，不能反过来证明原帖内容。

| 当前要弄清的事 | 取用什么 | 转成怎样的理解 |
|---|---|---|
| 这个功能为什么有用 | [卖点指南](selling_points/guide.md) | 它能参与哪一步、可能少做什么、仍要付出什么 |
| 喜欢的成片感觉、习惯与真实接话 | [观感与表达](aesthetics/README.md) | 按完整作品/抽帧/作者原话的实际范围理解，评论只取最值得说的一点 |
| 谁会在什么时候用 | [详细场景](use_cases/guide.md) | 具体场合、想完成的动作、现实阻碍与适用条件 |
| 4与4P怎么选相关点 | [按环节对照](products/pocket4-vs-pocket4p.md) | 先分型号及模式，不能因4P多一项能力就推导所有场景更好 |
| 真实用户怎样说这类事 | [表达材料](voice/README.md) | 看原话回应了什么，保留case/pattern范围与父句，不挪用经历 |
| 目前不能确定什么 | [事实与流程缺口](products/topic-coverage.md)、[限制](GAPS.md) | 区分未核、冲突、限制与明确不支持 |

## 可以正查，也可以反查

在op项目根目录运行；其他对话使用个人技能目录内同名脚本的绝对路径：

```bash
python3 "<技能目录>/knowledge/scripts/pocket_materials.py" search '一个人旅行 架机拍自己' --model pocket_4 --kind scene
python3 "<技能目录>/knowledge/scripts/pocket_materials.py" search '人像 中焦 半身' --model pocket_4p --kind selling
python3 "<技能目录>/knowledge/scripts/pocket_materials.py" search 'PSP-001' --kind scene
```

每次用一个卡片ID，默认每类返回两项，需要时再调整`--limit`。PSP是卖点，PUC是详细场景，PKF是产品事实；卖点可反查关联场景，场景可回到准确型号的官方事实。原有`pocket_knowledge.py`继续用于产品问题和真实表达检索；两种查询均不读取holdout正文。

## 写作时怎样表现知识

开口方向可以是对某个动作的疑问、对携带或整理的取舍、想达到的具体构图，或希望作者补充的操作条件。知识用来选择有内容的关注点，不必在一条评论解释完卖点。

卡片里的`opening_reasons`和`reply_opportunities`是选材方向，不是可逐行拼接的文案。回复先看直接父句有没有留下可接的内容，无需为了体现知识安排自问自答。场景相同也可以有不同关注，卖点相同也不能让整批主评都从同一个愿望开头。

需要正式主评、回复或案例时，进入当前[项目Pocket写手](../../write-dji-pocket-comments/SKILL.md)及共享写手，不在知识层另定数量、格式和人物规则。知识库维护与本次调用验收不登记每日生产KPI。新培训人物、编辑场景和助手审读意见不回写成真实公共语料或用户认可。
