# Pocket 已确认上下文

本页把影响后续调用的要求集中说明。它不是完整聊天转录，也不把助手计划、技术检查或历史稿件改成用户认可。

## 范围与历史调整

主库重点是Pocket4与Pocket4P，旧代用于辨认和比较。最初的大规模配额已按用户“调用这些够了，可以整理出来了，不需要那么多”收窄；之后用户另行授权近7天、三平台30篇研究，因此新研究单独登记，不恢复旧C3附件或旧采集队列。新批实际覆盖与未完成项始终见[动态覆盖](../COVERAGE.md)及[研究批次](../research/README.md)。

当前整合要求是“帮我验收，然后把所有上下文所有知识能力串联起来整成一个知识库，然后把没用的就清理掉”。统一指向现有维护源：产品事实、需求、真实表达、审美、比较、反馈和共用写作/研究/采集能力均可找到。清理依据引用和用途，不把原始证据、留出或未认可稿件因年代旧就删除。

## 产品、原帖与人物

目标产品型号、原帖实际拍摄设备和训练人物型号是不同字段。用户指定Pocket4P，可围绕4P取知识；原片设备未知仍须保留未知，不从标题标签、观看效果或角色设定反推原片。进入正文的能力按当前官方资料和成立条件核对。

公共第一人称属于原发言者。用户本人目前只明确拥有并用过Pocket产品线，具体代际和经历仍未知，依据见[本人素材](../feedback/records.jsonl)。原话、假想训练人物与真实消费者材料分别存放，互不替换。

## 自然表达与反馈

从处境、需求、熟练程度和当前态度理解为什么开口，避免按年龄、性别、职业套口吻。知识帮助说清具体兴趣，正文不必把参数、流程或背景全部复述；允许自然的直接喜欢、短答、附和和有内容的长句。

具体风格及最新数量、互动、格式要求在[共享写手](../../../write-consumer-comments/MODULE.md)维护；逐句反馈见[原句对照](../aesthetics/feedback.md)，作用范围随来源保留。旧“accepted/passed”文件名不等于当前获用户认可，不从历史通过记录恢复旧规则。

研究专题保留支持其他设备、不升级和犹豫的意见，不预设Pocket胜出。培训横测写作则按任务目标与共享写手当前分支选材：产品兴趣可以明确，硬能力与横测结论仍需证据。真实研究与训练选材的不同用途不应互相覆盖。

## 调用与维护

日常从[统一入口](../START.md)或统一简报查少量相关资料；`library.json`登记各类资料和实时技能路由。已读技能不循环加载。需要新评论时才进入共享写手，需要新链接证据时才交统一读取；本次整合不创建每日执行批次、培训量或新的定时任务。

用户于 2026-09-10 要求卸载本次接入的付费采集工具、不使用付费服务，因此原“Pocket与Osmo 360每日热评学习”停止执行；不按旧授权恢复。已有研究和来源保留，材料交接仍见[研究入库](../research/handoff.md)。

原事实和语料有来源与边界，编辑价值/场景假设保留标签，至少3个独立作品才可归纳表达规律。证据或媒体未读、固件冲突及未知父句仍保留，整合不能用文字补齐缺口。

上下文核对使用了当前目标、可见用户消息、任务工具能读回的历史消息和已有来源文件；有些历史任务返回空items，不能声称已完整恢复全部聊天。确认依据与读取边界见[本轮上下文审计](../_provenance/project/outputs/knowledge-consolidation-20260910/context-audit.json)，后续具体用户修正仍以其明确范围更新。
