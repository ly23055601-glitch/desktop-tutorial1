# 场景资料

本页保留原10张需求卡及原证据性质。2026-09-10另增3张单作品证据需求卡：已有3换4P的比较条件、外出前容量与挂绳、商场行走观看感受；见cards.jsonl中scenario_research_20260910_001至003。新增卡不是实际完整拍摄流程或人群结论。新补的详细拍摄任务、流程和卖点选材见[详细场景指南](../use_cases/guide.md)，两层分开，不把编辑假设新增为用户调研样本。

场景把“要做什么、卡在哪里、需要确认什么”连接到表达卡与产品事实。当前目标型号是 Pocket4 / Pocket4P；`target_models` 只表示写作服务目标，不证明历史作品使用这些型号。

[cards.jsonl](cards.jsonl) 原基线有 10 张卡：6 张借历史材料确认具体需求，4 张明确标为待补证的编辑假设。已连接产品库中核验通过的 34 条相关官方事实，共 47 处引用；`product_connections` 说明各条事实解决哪个问题，`open_product_questions` 保留每张卡尚未解决的事项。

`workflow` 是帮助写手分析需求的步骤，不是已核实的设备操作教程。`basis: evidence` 证明来源里出现过这些需要，不证明设备能满足它，也不代表 Pocket4 / Pocket4P 群体普遍如此。`editorial_hypothesis` 不能提升成用户洞察或真实经历。

调用时先读当前帖证据，选一个与内容确实相关的需要，再读 `voice_card_ids` 理解表达目的。具体产品能力从对应 `product_fact_ids` 取得，并同时读该事实的型号、条件与不可推论。场景也不分配说话者年龄、职业、家庭、购机或使用历史。

产品连接来自 `products/facts.jsonl`，本轮连接核查日期为 2026-09-06。事实是否成立与用户是否这样用分开登记：官方知识不会把 `editorial_hypothesis` 自动变成真实用户洞察，历史语言材料也不会因连接4/4P事实而成为这两款的群体研究。已核事实原始官网、文档定位及核验日期可沿产品库的 `source_refs` 回到 `sources/official.jsonl`。

例如，爬山场景目前仅有手势、遥控构图与云台保护相关事实，未证明帽子/肩带安装方案可行；亲子/宠物场景仍为编辑假设；Pocket4P官方攻略已明确支持宠物跟随，已补专门事实与模式关联，实际使用条件和地区/固件一致性仍需核对，不能由人物追焦事实推导宠物跟随。手机比较也没有建立同条件的画质优劣结论。10张卡的 `product_link_status` 均为 `verified_related_facts_with_open_questions`。

为场景登记产品事实时，应逐一检查适用型号和使用条件，保留原有限制。新作品能支持场景后，追加完整来源和独立作品统计，再审定是否改变 `basis`；不能只把假设标签删除。

场景2、3、4、9现增加 `new_public_post_support`：来源是已读train作品作者的具体流程负担或选择观点，不是评论。其记录、表达卡和支持范围与原历史需求/编辑假设分别列出；原basis保持，不把少量作者个案升级成人群规律，也不由作者说法认证功能表现。

2026-09-06 独立核查补齐了跨事实条件：使用FrameTap同时读取与Mimo互斥；讨论Pocket4旋转运镜同时读取不支持智能跟随；手机OTG导入同时核对手机、数据线、机身连接模式及不同接口步骤。主角跟随与“登记主角优先”对焦菜单也应明确区分。

同日产品复核发现4P胶片影调的慢动作支持存在中国与英国官方表述冲突，PKF-P4P-007已移入第5、8张卡的 `pending_product_fact_ids`，不计入已核能力。宠物场景加入PKF-P4P-030，并连同PKF-P4P-024/028保留倍率、模式和地区边界；其 `basis` 仍为编辑假设。

旧轮已停止扩量。场景002/003/004/005/009还包含`new_public_comment_support`，在原历史/编辑假设与新帖子支持之外单列C1/C2评论。C1可回到明确父句；C2关系为unknown，只支持独立观点或问题，不能证明回复顺序。scene009保留编辑假设，并非已证明的两款用户选择模型。
