# 每日培训草稿 KPI

更新日期：2026-09-15。当前表达与选材依据为 `2026-09-15-CW5.4.2`，横测链接先核对实际对照关系、比较轴、目标产品种草方向和证据，再按消费者立场选材；数量、state 和结构检查继续采用 CW5，命令仍为 `--profile cw5`。本文件维护考核口径；采集成功、产品知识和写作要求仍分别服从对应技能的当前文件。以后核对到新版时同步调整受影响口径，记录适用组与版本，不把本文快照永久当作最新规则。

## 单位与适用范围

`training_cw5` 质检分数是新增的质量诊断字段，不改写本文件既有的实交率、教学完整率、语义复核覆盖率或用户验收率。质量汇总必须同时显示基础质检数、深度质检数和未深审数；抽样深审结果不能直接当作整批语义通过。

- 输入位置用于输出分组：每次请求按原顺序每 10 个链接一组，尾组不足 10 个照常交付，失败与重复占原位置。完整集合统一采集，采集数量不受输出组限制。
- 写作与验收单位为“产品代码＋原帖／材料”的整组主评和回复。同日重复、改稿和验收不新增任务；同链接跨产品分别写作，采集证据复用。身份、跨日和引用以[台账契约](ledger-contract.md)为准。
- 主评、回复、长讨论组分别报告实际数；回复数、型号次数、每组链接数均不是质量分。培训或技能验收样例不计真实每日产量。
- 默认 `op/ow/om/dm/oq` 分别路由 Pocket／Nano／Mobile／Mic／Osmo 360，精确型号、卖点、使用场景及必要心理从对应知识入口按需取用。不能跨产品借功能、用人物经历补未知事实。
- 知识维护轮换顺序固定为 `op → oq → ow → om → dm`；这是维护排程，不改变当批按输入顺序的交付路由和 10 链接分组。

## KPI 与目标

| 指标 | 计算或判断口径 | 当前要求 |
| --- | --- | --- |
| 版本、路由与分组执行 | 核对两来源任务最新可读完成结果和现行文件；记录实际版本、产品路由；核对所有原输入位置的顺序、分组及结果引用 | 每批及全部输出组均落实；无法读取的更新如实说明，不声称已同步 |
| 输入闭环率 | 有稿件、明确结论或具体阻塞说明的任务数 ÷ 全部输入任务数 | 100%；不能漏项 |
| 读取成功率 | 合格证据包支持的去重待读链接数 ÷ 全部去重待读链接数 | 报告实际值；失败保留分母；成功标准只依统一采集技能 |
| 稿件实交率 | 已有首交稿件的任务数 ÷ 全部输入任务数，即脚本 `draft_completion` | 报告实际值；仅代表交付事实 |
| 教学完整交付率 | 当前版本满足本次适用写手要求、结构检查和内容复核的任务数 ÷ 同范围全部输入任务数 | 报告实际值，同时列未完成与未核；材料不足不移出分母 |
| 整帖理解与材料充分性 | 是否理解整体表达及主要吸引力，按需辨别主／副类型、场景及内容机制；需要声音、对白、步骤或完整叙事时是否有相应依据 | 完整交付每帖均须有充分依据；分类帮助选材，暂定或混合类型不自动失败，标签不能代替读帖 |
| 产品位置与选材适配 | 辨明目标产品是讨论对象、确认的记录工具、未确认设备还是使用联想对象；按具体活动与消费者关注查卖点、场景 | 完整交付每帖均须成立；任务产品标签不证明原片设备，同类不固定绑定功能、情绪或回复套路 |
| 每条主评的产品兴趣 | 每条分别有目标产品相关的感受、偏爱、用途或疑问；产品语境明确且已展示效果时，直接喜欢画质、色彩、气色等也可成立 | 完整交付每条均须成立；不强加型号、经历或追问，无关泛夸、重复赞叹和单纯报拥有不能替代 |
| 有效讨论与数量 | 使用当前写手数量；CW5 的具体完成条件见下节 | 完整交付每帖均满足；不能用重复附和或拆句凑数 |
| 硬错误 | 型号／功能错误、编造原帖内容、来源归属错误；分别记内部、已交付、未修复数量 | 目标 0；发现即修复并保留历史记录。合规假想人物经历不计硬错 |
| 内容复核覆盖率 | 完成实际内容审阅并有记录的当前交付任务数 ÷ 实交任务数 | 100%；覆盖和通过分开，独立审稿另记，脚本通过不能代替内容判断 |
| 内容复核矩阵完整性 | 当前版本逐任务记录整帖理解、证据充分性、事实、自然度、产品兴趣、差异、讨论价值；触发横测时另有对照对象／比较轴／证据强度 | 100% 的已交任务有矩阵；缺一项记未核，不得用四个旧布尔项或脚本通过代替 |
| 证据与知识交接完整性 | evidence pack、产品 `knowledge_handoff`、型号状态和来源／核验时间均可追溯；体验材料记录实际阅读范围 | 交付前逐任务可追溯；缺项保留为受限或未完成，不把文件存在当作已看／已听 |
| 首稿验收率 | 无需修改即获用户明确认可的首稿任务数 ÷ 用户已明确审阅的首稿任务数 | 前 7 个实际执行日先记录，另报审阅覆盖率；零分母为“暂无数据” |
| 效率与返工 | 接单开始至首交的墙钟耗时、已记录外部阻塞区间、用户反馈驱动的修改轮次 | 前 7 个实际执行日先记录，不设分钟门槛；回复增加不算效率加分 |

“内容复核覆盖”只说明看过并记录，可能仍有问题；“教学完整交付”要求相关判断成立，仍不代表用户认可。不设混合总分，不用结构数量抵消事实或表达问题。

## CW5.4.2 教学完整交付条件（结构沿用 CW5）

以下为当前[共享写手](/Users/luocaihua/.codex/skills/write-consumer-comments/MODULE.md)规则的 KPI 映射，以该文件当前版本为准。

1. 先理解整帖，简记产品角色、主要吸引力和最顺的表达方向，需要辨别细类时再读[帖子类型与产品话题](/Users/luocaihua/.codex/skills/write-consumer-comments/references/post-type-selection.md)。每条主评的产品兴趣独立成立：产品明确且效果已展示时可直接喜欢，相关场景期待和假想使用感受也可由整帖引起，不要求原帖出现同一地点、人物或动作。任务产品或历史标签不能证明原片设备、作者测评对象；主观喜欢不证明客观能力或效果全由设备造成。产品事实、原帖内容与假想人物经历分开。
2. 每帖以 **3–4 条主评**为主。确实只有两个不同且成立的角度时可写 **2 条**，在选材记录说明具体原因。
3. 每帖选 **1–2 条主评，各展开 5–8 条楼中楼**；其余主评按内容配 **0–4 条回复**。逐条核对全部回复，包括第 5–8 条的事实、来源、人物与父句。
4. 表达自然，主评逐条成立产品兴趣；回复逐条检查直接父句、声音、人物和事实，讨论价值看整楼。短问、调侃、普通附和可留，不要求每人新增卖点，但不能靠连续认同、重复解释、轮讲功能、共同设计方案或统一下单凑数。先并排审同帖主评与回复，再看同组、前组和最近 7 个执行日的相关稿，比较真正想说的事及语气，不用跨帖长短掩盖本帖同一种声音。自然长句可留，短句说清可停，减少反复背景＋用途＋价值总结及无用列举，不设字数、比例或逗号门槛。同帖实际点名时自然使用已有准确全称／简称，不编简称，也不靠换称呼证明差异。参数、原片、补拍和教程须有实际信息需要，有更新线索才等后续，不默认追问博主。
5. 最终稿与训练 state 绑定 SHA256，保存实际 `--profile cw5 --json` 检查报告及内容判断。机器只检查每帖 2–4 主评、每楼最多 8 回复、至少一楼达到 5 回复等结构；它不能判定以上语义条件。

材料、产品关联或讨论不足时先重选或补足，仍不足可交付成立的部分与缺口说明，但记“教学未完成”。不能删掉回复后照常算完整，也不能为满足 KPI 编造事实。

选材记录沿用自然文字简记整体意思、产品角色、主要吸引力和表达选择，必要时说明类型或知识取舍，不把它们拼成正文公式。审稿先读原帖与正文，再看分类和创作解释；不设分类明确率、分类配额或机器分类质量分，不要求每帖填满全部类型字段。历史类型占比不用于产量、选题优先级或卖点分配，429 条历史分类记录与扩展方向不算本轮新增任务或用户认可案例。以上变化纳入已有自然度与差异审查，不新增 KPI 指标或逐条教师表。

用户当次明确改变数量或格式时，记录要求及适用范围，按该要求判断交付，不算默认 CW5 结构达标；检查器不支持的部分明确说明，不能伪造通过。事实、自然度和每条主评的产品关联仍须审阅。

## 怎样留档与汇总

`ledger.json` 保留已有实交、反馈和计量结构；共享训练 state 不新增评分字段。现有 `daily_kpi.py` 不读取正文、检查报告的 profile 或当前写手版本的教学完成结论，**不能从 `draft_completion` 或四个复核标记推算教学完整交付率**。当前写手的直接表达、产品角色、横测比较轴、同帖声音与整楼价值均属于内容复核，使用同一 cw5 结构配置不能证明已完成这些判断。

每批在独立 KPI 日报中追加“教学完整交付”表，每个任务／版本一行，记录：任务引用、适用写手版本或当次数量要求、稿件／state／结构检查／语义审查引用、主评数／回复数／5–8 回复组数、2 主评例外理由（如适用）、状态及缺口。语义审查沿用已有审稿记录，不新增逐句教师打分表。

- 状态分为“完整”“未完成”“未核”。只有全部适用条件有实际依据且成立时记完整；已知缺材料、产品关联或讨论等不足记未完成；尚未审阅或记录不足记未核，缺记录不推定通过，也不直接判定正文不合格。
- 汇总显示“确认完整数 ÷ 本范围全部任务数”，另列未完成、未核；没有可适用任务为“暂无数据”。这项目前需结合稿件与审查记录汇总，不称为脚本自动结果。
- 首交教学结论随首交保存，修订追加新版结果；当前教学完整率看当前版本，原版本与首稿用户验收不可回写。KPI 日报按任务引用去重，跨产品分别计。
- 旧版稿件保留当时适用规则和结论，不因写手更新改写成失败或通过。跨版本报表按实际表达版本分列，CW5、CW5.1、CW5.2、CW5.3 即使使用同一结构 profile 也保留各自范围；各版本新任务完成率的分母只含适用该版本的新任务。旧稿专项重审、修订仍归原任务，不增加新产量。

收尾展示：**输入／实交／教学完整、主评／回复／长讨论组、阻塞与未完成、硬错及自检问题、用户验收、耗时与返工**。内部审稿和证据保存在独立文件；评论页顶部统一标注“培训用假想消费者草稿”。

首 7 个实际执行日仍按原计划累计，不因版本更新重置，也不把无新任务日计入。第 7 日合并真实台账，按写手版本说明可比范围、首稿审阅覆盖及样本不足，据此提出下一阶段验收率和效率目标，待用户采用后生效。
