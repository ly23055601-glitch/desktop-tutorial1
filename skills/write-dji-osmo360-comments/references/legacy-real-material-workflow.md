# DJI Osmo 360 评论运行规则

固定服务 `DJI Osmo 360 / Osmo 360 II`。稳定写作偏好已经固化在本文件；普通任务不得读取其他项目、旧对话、旧批日志或历史成稿正文。

默认只交可复制的纯净稿：每个可读链接 3 条主评论，每条配 2–4 条用户间楼中楼。评论正文不得出现半角或全角空格；产品名写作 `Osmo360`、`Osmo360II`、`360二代`。本版规则只应用于之后收到的新链接，不触发对已交付成品的返修。只起草，不发布、点赞、私信或操作账号。

## 快速运行路径

1. 需要从抖音、小红书或 B站链接读取或采集时，先完整读取并遵循 [统一读取 Skill](../../read-social-links-with-social-helper/MODULE.md)，一次性交给它当前请求中这些平台的完整待读取链接集合并保留原序号，由它统一去重、分平台、分批和处理失败项。不得为了逐链接胶囊、媒体取样或写作分工而拆成多次单链接调用。它是 Chrome、社媒助手、分平台批次、小红书节流、字段、评论深度、问题交人工、导出下载、账本及一次证据验收的唯一规则源；本技能和 references 中的旧采集描述均不得覆盖它。问题项保留原序号及已有证据交人工，不以补读重采失败作品。微博等其他平台按全局规则登记完整集合、批量组织，以已连接外部 Chrome 单次读取原页可见内容，问题项同样交人工；充分用户材料可直接使用。
2. 复用统一证据包的原序号、成功/失败状态、媒体和限制；本技能只追加 Osmo 360 型号门禁、媒体取样、写作和 QA。不得自行增加连接探测、补抓或切换读取方式。
3. 有本地媒体时用 `scripts/sample_media.swift` 一次生成轻量联系表：普通短视频 5 帧、长视频 7 帧，只有深审才用 `--deep` 取 9 帧。再将每条压成短证据胶囊：`序号/ID｜平台｜可读性｜评论可见性｜型号证据｜可见时间/地点/场景｜2–3 个画面锚点｜可用产品点｜不可推断`。音频或完整视频需要在首次内容计划中按统一读取 Skill 取得；本地证据不足时交人工，不追加下载或让失败作品重新入队。
4. 8 条以上按 6–10 条分块并行起草；子任务只接收本块胶囊、媒体路径和一页规则卡，不继承旧对话或其他块日志。规则卡必须写明正文零空格、固定 `PPC`、两条产品主评采用“时间+地点+场景+使用价值”、第三条为纯内容互动，以及二代称呼与专属卖点的证据门禁。楼中楼通常先写 2 条，有真实补充或分歧时再加到 3–4 条。
5. 合并后只运行一次结构与同质化检查，随后只返修命中组并复检。默认不做第二遍全量逐条审稿，不生成审稿日志，不临时重建历史 baseline。
6. 目标是在页面可访问、普通短视频无需深审时，将批量平均处理时间压到约 1 分钟/可读链接以内；网络、登录、长视频或证据冲突不纳入硬承诺，但不得让单个失败链接拖住整批。

运行批量检查器：

```bash
python3 scripts/check_comment_homogeneity.py draft.md --product-policy strict
```

媒体取样：`swift scripts/sample_media.swift <media_root> <output_dir> --items-file links.tsv`。按链接清单运行才能同时记录缺失项；脚本不覆盖已有目录，失败项写入紧凑 manifest 后继续。

跨批去重可把最近成品作为 `--baseline <path>` 交给脚本静默读取；不要把 baseline 全文打印或注入模型上下文。二代证据按链接传 `--allow-second-gen-id <ID>`，批量不得使用整批放行参数。

## 何时升级深审

仅在以下情况扩大取证：型号或水印冲突；教程、测评、价格、参数、竞品；超过 60 秒且多场景；口播是主信息；默认抽帧不足两个可靠锚点；涉及夜景、拼接、增稳或画质因果；评论区争议是写作核心；检查器提示疑似虚构、硬植入或系统性近重复。

精确参数、兼容、价格或竞品结论只核验正文实际需要的那一项，不做每批全量产品研究。无法确认就改成真实疑问。

## 证据与产品边界

- 取证优先级固定为：实际画面、字幕、口播、可见操作 > 结构化作品字段。标题、正文、作者文案、标签和摘要只用于核对型号、候选地点等客观事实，不用作评论主题、情绪、金句、使用效果来源或叙事主线。具体地名若不能由画面、字幕或口播交叉确认，改写为画面可见的泛化地点。
- 每条主评至少含一个只有读过链接才能写出的细节；一条只抓一个主要瞬间。素材只有 1–2 个可靠锚点时允许换角度共用，不能为凑三个而编造。结构化作品字段不能代替画面、字幕或口播证据。
- 时间优先写画面可确认的清晨、白天、傍晚、夜里、放学后等；精确钟点只取自画面、字幕或口播。地点优先写画面确认的校园、老街、泳池、公路等；具体地名无法核验时不从作者文案硬补。
- 实际媒体可读但时间或地点仍无法确认时，只补查一次字幕、口播或更多画面；仍无证据便将该链接标为“时间/地点证据不足”并跳过，不用作品字段、常识或模板词硬凑四要素。
- 正文、画面与媒体都不可读时不写通用稿。评论区不可见时按平台基线写，不声称复刻了原评论区。
- 只有标题、机身、水印、字幕、口播或可靠作品字段明确支持时，才能写 `Osmo360II`、`360二代`或`这台二代`；使用二代专属卖点还须单独核验该项事实。代际不明时只用通用称呼。
- 链接实际不是 Osmo 360 内容时停止产品露出配额；不得把 Action、Pocket、Nano 或竞品强写成 360。
- 参数与比较只写有来源和条件的结论；不要从成片反推机位、防抖、拼接、画质、续航或故障原因。

## 三组评论

- 可确认的 Osmo 360 链接固定为 `PPC`：第 1、2 条是产品种草主评，第 3 条是纯内容主评，不再轮换产品槽位。第三条不出现产品称呼或卖点，也不强制四要素，其楼中楼优先围绕内容本身接话。
- 两条产品主评都要自然包含“时间+地点+场景+使用价值”，四项共同描述一个瞬间，不按固定顺序罗列。时间只写媒体可确认的宽泛时段，精确时间须有画面、字幕或口播；地点优先写画面可见类型；场景只抓一个动作或瞬间；使用价值一次只承接一个产品点：旅行、校园或独自拍摄落到先完整记录再后期选视角；骑行或运动落到人物与环境同时保留或后期切换前后视角；长杆、高位或多人场景落到第三人称或更完整环境；小行星和创意运镜落到同一份全景素材的不同构图玩法。长杆或高位玩法须有杆体、拍摄操作或明确说明可见，不能仅从成片倒推机位；夜景、跟随、可换镜片等代际卖点仅在型号明确且对应事实已核验时使用。
- 两条产品主评使用不同称呼并承担不同任务。可轮换 `Osmo360`、`Osmo360II`、`大疆360`、`360二代`、`这台全景机`、`这个小相机`、`360画面`、`全景视角`、`这个模式`、`全景素材`、`这台二代`；每条最多一个称呼。
- 产品词必须和该帖的画面、拍摄动作、操作、后期结果或真实疑问直接相连。删掉产品词后仍要有明确内容，不能只剩万能夸赞。
- 两条产品主评都要像素人发现了具体用途并显露需求被触发或心动；每个链接至少一条可直接表达“被种草了”“有点想入”“这种用法确实心动”等购买意愿，另一条可以带真实顾虑或条件，但仍保留兴趣。同一链接避免复用同一句心动表达。不得虚构已经买过、用过、带去拍过或长期体验。
- 主评像临场留言，不是完整复盘或产品总结。允许短句、停顿、轻吐槽、没回答的问题和没说满的结尾。
- 主评和楼中楼正文均不得含 ASCII 空格或全角空格；不要为了品牌官方写法保留 `Osmo 360`、`Osmo 360 II` 里的空格。标题行的 Markdown 结构空格不计入正文。
- 同一链接至少一条主评不用逗号复句；出现“前面—后面—最后”串联多个镜头时，删到一个动作或瞬间。
- 避免 `A、B、C` 三连景、逐镜解说、统一反转、机位侦探、参数党总结及“本质上/核心优势/产品价值/适合哪类人”等策划腔。
- 楼中楼要接话而非复述主评；数量和路径不整齐，可附和、补一个条件、轻微反驳或停在分歧处。不要把剩余镜头拆成回复清单。
- 不虚构“我买了、我用过、我带去拍过”等经历，也不虚构职业、关系、销量、口碑、故障或群体共识。

## 平台语态

- 小红书：生活代入、真实顾虑、轻量情绪，中短句。
- 抖音：先说动作或反差，节奏更短，不补完整评测。
- B站：可说测试条件、时间点和工作流，但保留边界。
- 微博：观点先行，理由简短，可有有限分歧但不阵营化。

只有跨平台改写或平台语态难判断时才读 [references/platform-voices.md](../references/platform-voices.md)。用户明确要求人群心理时读 [references/audience-psychology.md](../references/audience-psychology.md)；涉及热点时读 [references/trend-and-timing.md](../references/trend-and-timing.md)；涉及精确产品或竞品事实时读 [references/product-knowledge.md](../references/product-knowledge.md)。社媒采集始终读取 [统一读取 Skill](../../read-social-links-with-social-helper/MODULE.md)，不再使用本地 `social-helper-reading.md` 作为规则源。仅当检查器出现系统性同质化或用户要求专项审稿时读 [references/low-homogeneity.md](../references/low-homogeneity.md)。

## 状态与交付

10 条以上或预计跨轮续接时，运行 `scripts/init_fast_batch.py` 建立轻量清单和状态；小批次不建状态。状态只保存路径、ID、成功/失败、二代许可与 QA 计数，不保存评论全文、工具输出、账号数据或浏览器日志。

续接时只读状态与未完成胶囊；已有媒体 manifest 时不重抽帧，不重抓成功链接、不重下已核验媒体、不重读旧稿。已交付历史文件不回改，除非用户明确要求。
