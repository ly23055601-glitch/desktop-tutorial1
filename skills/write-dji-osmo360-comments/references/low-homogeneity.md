# 批量低同质化专项

仅在检查器出现系统性重复、跨批续写或用户明确要求专项审稿时读取。普通批次直接执行 `SKILL.md` 快速路径。

## 轻量账本

每条只记录：`ID｜锚点类型｜评论任务｜开头类型｜句长/标点｜产品称呼/卖点｜回复数｜文本指纹`。滚动保留最近 30 个链接或 150 条主评的分类与指纹，不保存旧稿全文或审稿日志。

批量按 6–10 条分块。各块预分配不同的高频语气、产品卖点和回复数组合；子任务只接收本块证据、一页规则卡与禁用指纹，并使用 `fork_turns="none"`，不得继承旧对话。规则卡必须包含正文零空格、固定 `PPC`、两条产品主评四要素和二代证据门禁。

## 人工判断重点

- 同一链接三条主评应承担不同任务，不固定“情绪—问题—产品总结”。
- 一条只抓一个主要瞬间，最多并列两个必要对象；删除三连景和逐镜头复盘。
- 固定使用 `PPC`；跨链接通过锚点、时间地点表达、卖点、开头、句长和楼中楼路径去同质化，不再靠移动产品槽位。
- 两条产品主评不能都只说“拍得全/后期选方向”；先换关注任务，再换句法，最后才换产品称呼。
- 同一链接至少一条主评不用逗号；开头、句长、产品词在句中的位置和漂亮收尾不要整齐。
- 楼中楼不复述主评，也不提前完整说完另一组；回复数 2–4 条，通常先写 2 条，有真实信息才增加。
- 高频指纹如“我还以为、才发现、那一下、到底装哪儿、求幕后”可以单用，但相邻链接不连续复用。

## 检查与返修

```bash
python3 scripts/check_comment_homogeneity.py draft.md \
  --baseline recent.md \
  --product-policy strict \
  --allow-second-gen-id <已确认ID>
```

批量二代许可逐链接传入；不得使用 `--allow-second-gen` 整批放行。baseline 由脚本静默读取，不向模型打印正文。

仅返修以下命中：完全或近似重复；换产品名式重复；同组/跨组同义复述；型号或产品配额错误；产品词无锚点；回复数与句法形成局部矩阵。

改写顺序：换评论任务 → 换信息入口 → 换句长与停顿 → 换产品词在句中的位置 → 调整楼中楼。第 1、2 条产品与第 3 条内容的槽位不可移动；只换同义词不算去同质化。

检查器通过后只抽查命中链接和风险项，不再对全部主评与回复做第二遍审稿。若修改过结构，复跑一次检查器即可。
