## MOBILE-USE-013｜猫沿着沙发边慢慢走，先把视角降下来

**型号**：Osmo Mobile 8；场景编辑：2026-09-07（不替代事实核验日期）

**可关联角色**：[猫狗拍摄者](../audiences/guide.md#mobile-aud-005)

**发生时刻**：猫沿着沙发边活动，偶尔停下闻一闻物品。拍摄者想从接近它的高度留住侧脸和步态，不希望一直从上方俯拍。

**想完成的拍摄**：先用低机位构图记录单只猫，确有跟随需求时再选择已核的一代模块路径。

**具体难点**：想拍猫的表情，却常常只拍到背部；追着跑又容易把拍摄动作变成干扰。

**卖点如何参与**：

- 先安排较低的侧面机位，按 Mobile 8 的正握低机位方法调整平移轴。
- 从短段手持开始；需要一代模块跟随时，让模块与手机镜头朝同一只猫，并在系统相机或适用第三方拍摄 App 试拍。
- 保留距离等待猫自己进入画面，拍完检查表情和运动方向是否符合预期。

**对应卖点**：[正握也能安排低机位](../selling_points/osmo_mobile_8.md#mobile-sell-007)

**可能价值**：可能让构图更贴近猫的活动高度，并把追拍变为等待与观察。

**心理取舍（假设）**：想要——想拍到猫正在做什么，而不是让猫配合自己的镜头。；犹豫——担心一拿设备靠近，原本自然的动作就停止。；取舍——愿意少追几步、多等片刻，接受并非每次动作都能完整拍到。

**可供训练选择的表达方向**（分析线索，非待复制评论）：

- 低视角改变的是画面观看方式
- 跟随与不干扰宠物之间的距离选择
- 单只猫的短动作如何构成足够具体的记录任务

**可选细节**（只有在当批训练人物中设定，或由真实材料证实后才能使用）：待虚构或待实证：鼻尖停在沙发边某个物件前；待虚构或待实证：从侧脸转到背影后停止追拍；待虚构或待实证：等猫自己再次进入预留画面

**可能适用的话题语境**（假想条件，实际选材先读原帖）：假想话题条件：原帖讨论拍猫总是俯视或如何低机位拍摄；假想话题条件：原帖问 Mobile 8 一代模块能否跟猫狗

**不能据此替真实原帖补写**：不能假设原帖宠物怕镜头或表现出特定情绪；不能把假想片段当成低机位或跟随实拍效果证明

**何时不需要这项能力**：猫已经静止在合适位置时，普通手机固定构图也能完成，没必要强行启用跟随。

**关键条件摘要**：一代模块在 Mobile 8 的猫狗路径推荐单只，不能扩展为任意动物或物体。；模块跟随不在 Mimo 内使用；镜头方向须一致。；低机位受握持、手机负载与轴范围限制，不代表不用弯腰。

**不可推论**：所有动物都能自动识别。；猫突然加速或遮挡也永不丢失。；降低机位就保证宠物不受打扰。

## MOBILE-USE-014｜两只宠物同时出现，先明确这次想跟哪一只

**型号**：Osmo Mobile 8P；场景编辑：2026-09-07（不替代事实核验日期）

**可关联角色**：[猫狗拍摄者](../audiences/guide.md#mobile-aud-005)

**发生时刻**：猫和狗都来到同一片活动区域，拍摄者这次只想记录其中一只叼着玩具走过来的动作。选择目标这一步，比笼统地打开跟随更重要。

**想完成的拍摄**：在模块2追踪预览中按支持方式选择猫或狗目标，再检查手机实际取景。

**具体难点**：看到屏幕有目标框不等于手机最终构图合适，也不能据此相信目标不会因遮挡而变化。

**卖点如何参与**：

- 安装模块2并确保模块镜头与手机摄像头同向，在光线和主体大小合适的位置开始。
- 进入 FrameTap 的模块追踪预览，按猫狗对应的检测和选择方式确定这次要拍的目标。
- 另外检查手机画面与目标范围，需要时做画面校准；不把模块预览直接当作成片画面。

**对应卖点**：[在模块预览里指定要跟随的物品](../selling_points/osmo_mobile_8p.md#mobile-sell-002)

**可能价值**：可能帮助拍摄者先表达清楚拍谁，再观察跟随是否服务这段动作，而不是把出现的每只动物都当成必须兼顾的对象。

**心理取舍（假设）**：想要——想给某只宠物留一段有主次的画面。；犹豫——担心另一只突然进来就让原本想拍的细节被忽略。；取舍——愿意先选目标并接受中途回看或重设，不把识别框当成永久锁定保证。

**可供训练选择的表达方向**（分析线索，非待复制评论）：

- 多对象场景里选择比盲目开启更重要
- 模块预览与手机构图的两个检查层次
- 记录一只与记录全部的不同任务

**可选细节**（只有在当批训练人物中设定，或由真实材料证实后才能使用）：待虚构或待实证：另一只宠物从背景短暂穿过；待虚构或待实证：目标靠近后手机画面需要重新留空间；待虚构或待实证：回看时决定只保留没有遮挡的短段

**可能适用的话题语境**（假想条件，实际选材先读原帖）：假想话题条件：原帖讨论模块2选择猫狗跟随目标；假想话题条件：原帖询问 FrameTap 模块预览为何与手机构图不同

**不能据此替真实原帖补写**：不能把原帖中多只动物的身份、习惯或先后顺序补写出来；不能假设真实组合已经成功保持目标身份不变

**何时不需要这项能力**：想拍的是两只宠物同时在固定区域互动时，合适的固定广角构图可能更直接；手机镜头能力另核。

**关键条件摘要**：本卡使用模块2自己的预览，不是手机投屏；手机最终构图另查。；猫狗跟随需满足主体大小、光线、朝向等要求；不能用人物手势控制猫狗。；出现选择框并不保证快速运动、遮挡或多目标时持续稳定锁定。

**不可推论**：点选后永远不会换目标。；模块屏幕看到的就是手机最终成片。；人物手势能让宠物启停录像。

## MOBILE-USE-015｜已有 Mobile 8 和模块2，先核固件再试拍狗的短移动

**型号**：Osmo Mobile 8；场景编辑：2026-09-07（不替代事实核验日期）

**可关联角色**：[猫狗拍摄者](../audiences/guide.md#mobile-aud-005)、[已有云台或曾经闲置的用户](../audiences/guide.md#mobile-aud-013)

**发生时刻**：拍摄者已经拥有 Mobile 8，后来添了模块2，想记录狗在室内叼回玩具的短段移动。开始前需要确认扩展配件在这台云台上能用到哪些能力。

**想完成的拍摄**：把 Mobile 8 的模块2适配、目标类型与按键操作落实到一次猫狗跟随试拍。

**具体难点**：新模块的宣传中有不同云台共用和专属能力，容易把装上新配件理解为整机变成 8P。

**卖点如何参与**：

- 核对云台已安装支持模块2的固件，再按该组合连接与朝向要求安装。
- 选择光线和背景适合的短活动范围，按 Mobile 8 已核按键路径对狗试跟随。
- 需要低机位时按本体握持方法调整并重新检查取景；回看后再决定是否适合实际记录任务。

**对应卖点**：[已有Mobile 8可核对模块2扩展用途](../selling_points/osmo_mobile_8.md#mobile-sell-012)、[正握也能安排低机位](../selling_points/osmo_mobile_8.md#mobile-sell-007)

**可能价值**：可能让已有设备围绕新增宠物任务继续使用，同时避免为未支持的高级操作形成错误期待。

**心理取舍（假设）**：想要——想让已有设备服务新的宠物记录习惯。；犹豫——担心买了配件才发现想用的触屏功能属于另一型号。；取舍——先确认这次只需要猫狗跟随，接受本型号的操作方式，再判断扩展是否足够。

**可供训练选择的表达方向**（分析线索，非待复制评论）：

- 扩展配件解决具体任务而非代替升级整机
- 固件条件怎样影响已有设备的使用判断
- 需求是跟狗还是想要全部高级触屏操作

**可选细节**（只有在当批训练人物中设定，或由真实材料证实后才能使用）：待虚构或待实证：使用前在设置里核对固件版本；待虚构或待实证：把狗的移动范围限定在一段室内地面；待虚构或待实证：试拍后发现自己并不需要物体手动框选

**可能适用的话题语境**（假想条件，实际选材先读原帖）：假想话题条件：原帖问 Mobile 8 能不能用模块2；假想话题条件：原帖讨论已有云台拍宠物是否需要升级

**不能据此替真实原帖补写**：不能认定原帖作者已购买配件或升级了固件；不能把假想成功试拍作为适配清单外组合的证明

**何时不需要这项能力**：现有 Mimo 或一代模块路径已满足任务时，不需要因为新配件出现就自动更换。

**关键条件摘要**：固件必须满足 Mobile 8 对模块2的适配要求，不能只验证能吸附。；8 的模块2猫狗跟随与 8P 触屏、高级设置、其他物体手动框选分开。；模块和手机镜头同向；非人物主体大小、光线和遮挡条件仍限制效果。

**不可推论**：加模块2就等于升级成 8P。；可以在 Mobile 8 的 FrameTap 上手动框任何玩具。；模块2已确认沿用一代模块收音能力。

## MOBILE-USE-016｜宠物已经安静休息，用手持转向交代它周围的小环境

**型号**：Osmo Mobile 8P；场景编辑：2026-09-07（不替代事实核验日期）

**可关联角色**：[猫狗拍摄者](../audiences/guide.md#mobile-aud-005)、[手机影像爱好者](../audiences/guide.md#mobile-aud-011)

**发生时刻**：猫狗安静待在自己的垫子旁，旁边还有常用玩具和窗边光影。拍摄者想用一个缓慢转向把环境带到宠物身上，而不是让宠物起来活动。

**想完成的拍摄**：以手持机械增稳与可控水平转向，把环境和静止宠物串成一个短镜头。

**具体难点**：跟随功能很容易成为默认主角，反而忽略这段画面并没有移动目标要追。

**卖点如何参与**：

- 决定先出现的环境细节和最后停住的宠物位置。
- 按想要的手柄响应选云台模式，缓慢水平转向并在主体位置停下。
- 回看速度、背景和主体占比；宠物不移动时不必开启模块跟随。

**对应卖点**：[用机械增稳承接手持移动镜头](../selling_points/osmo_mobile_8p.md#mobile-sell-006)、[水平连续转动，给环绕构图留出空间](../selling_points/osmo_mobile_8p.md#mobile-sell-015)

**可能价值**：可能让拍摄者把注意力放在观看顺序和节奏上，保留宠物正在休息的状态。

**心理取舍（假设）**：想要——想拍出宠物日常所在的小世界，而不是只拍一个孤立特写。；犹豫——不想为了展示设备能力引逗宠物起身。；取舍——接受镜头朴素、动作少，把想保留的平静作为拍摄选择。

**可供训练选择的表达方向**（分析线索，非待复制评论）：

- 静止主体也能对应云台卖点
- 运镜服务观看顺序而非追逐目标
- 选择不用智能跟随本身的任务判断

**可选细节**（只有在当批训练人物中设定，或由真实材料证实后才能使用）：待虚构或待实证：先从玩具或垫子一角转到宠物；待虚构或待实证：回看后缩短环境铺垫时间；待虚构或待实证：宠物醒来后停止拍摄而非继续引导

**可能适用的话题语境**（假想条件，实际选材先读原帖）：假想话题条件：原帖展示宠物安静日常或环境镜头；假想话题条件：原帖讨论手机云台除了跟随还能怎样用

**不能据此替真实原帖补写**：不能为原帖宠物编造睡眠、情绪或健康状态；不能把假想手持片段写成实际防抖测评

**何时不需要这项能力**：一张静态照片已能表达宠物与环境关系时，无需多加转向；场景安静不代表必须录像。

**关键条件摘要**：这是手柄控制的机械运镜，和识别宠物的智能跟随分开。；平移轴无限位不等于全轴无限转动或全景拍摄。；机械增稳不保证暗光画质，也不会消除所有手持移动起伏。

**不可推论**：云台会自动理解宠物休息的氛围。；转一圈就是可自由观看的全景视频。；手持视频一定比普通手机静态构图更好。
