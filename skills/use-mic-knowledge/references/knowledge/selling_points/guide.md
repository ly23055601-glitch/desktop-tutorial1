# DJI Mic 产品卖点与用途价值

补充日期：2026-09-07。本层共有 30 张卖点卡：Mic 3、Mic Mini 2S 各 9 张，其余四款各 3 张。用途价值和角色适配是依据功能进行的编辑归纳，不是官方效果承诺、消费者研究或实测比较。

每张完整卡包含精确型号与部件、具体触发情境、产品事实编号、可能适用的角色、用途价值、适用条件、不能推出的结论、表达方向和当前来源复核。阅读表先用于选材，引用时打开完整卡或运行检索；不要只摘标题作无条件宣传。

## 按当前任务选卖点

| 要解决的事情 | 可查的卖点方向 | 继续核对 |
|---|---|---|
| 出镜、演示动作、佩戴搭配 | 轻量、固定方式、背夹方向或换盖 | 衣物、固定、防脱与配件是否另购；不能保证人人无感 |
| 留存某段录音、后期处理 | 发射器内录、文件类型、导出路径 | 是否真正开录、存储与续航、盒型、密码及覆盖方式 |
| 采访、圆桌、多机位 | 发射器数量、声道输出、监听、时间码 | 输入数量不等于独立输出轨；检查宿主、接口和软件 |
| 人声处理与现场调整 | 降噪挡位、音色、自动增益 | 按实际声音试录选择；连接模式和控制端会改变能力 |
| 手机、相机、DJI 机身之间配接 | 标准或手机版接收器、蓝牙、OsmoAudio | 主机兼容、所需配件、输入数量与功能差异 |
| 拍摄间歇补电、团队排期 | 部件续航、充电盒补电和受控快充数据 | 条件是否关闭内录/降噪，累计续航是否被误作连续录制 |
| 继续使用已有设备 | 明确的旧部件复用方向 | 复用不会给旧发射器新增内录，也不保证统一省钱 |

## 必须连同卖点保留的区别

- **Mic 3 与 Mini 2S 的文件处理不同。** Mic 3 的双文件内录可保留原音和处理版；Mini 2S 卡描述原文件或处理文件的选择，不能照抄成同时双文件。两者内录格式均不能直接推给相机或手机录制音轨。

- **人数、接收器和声道分别判断。** 标准接收器的四发能力不能套用到手机版接收器；3.5 毫米输出不能借“四声道”短句宣传为相机四人独立轨。Mic 3 四发八收也不是八位说话人。

- **各代连接功能不同。** Mic 2 手机蓝牙直连时内录、智能降噪不可用；Mini 与 Mini 2 没有内置录音存储。不能因为同属 Mic 把新款内录卖点迁移过去。

- **降噪与音色是可选择的处理。** 功能存在不证明实际开启，也不证明所有人声更好听、所有噪声消失、平台成片必然清晰。

- **续航分部件、模式与盒型。** 不把关闭内录和降噪的测试时长套到开启后，不把累计补电写成连续录制；手机版小盒与标准盒的导出能力也不同。

- **用途价值保留推导性质。** “可留原音供后期选择”可由文件能力推导；“一定不返工”“客户因此更信任”“直播转化更高”“比所有竞品稳定”等结论没有因此得到证明。

## 如何检索与接入写作

以下命令在技能目录运行，也可将脚本改为绝对路径从任意目录调用：

```bash
python3 references/knowledge/scripts/mic_selling_points.py --model mic_3 --limit 20
python3 references/knowledge/scripts/mic_selling_points.py '采访内录备份' --model mic_mini_2s --format json
```

个人技能使用 `scripts/mic.py selling-points`，同样支持 `--model`、`--limit` 和 Markdown／JSON。未给问题时列出所选型号卖点；未给型号时每张卡标明归属。结果展开事实、原来源及实际核验日、本次复核、条件和限制；底层依据未核验或当前复核未解决时，该卡移到 `unresolved`，不作为肯定依据。

需要评论时从既有共享写手完成表达。卖点卡只负责产品价值选材，角色卡只提供假设；不另定句式、强行把每条评论改成完整产品介绍，也不保存假想购买经历。
