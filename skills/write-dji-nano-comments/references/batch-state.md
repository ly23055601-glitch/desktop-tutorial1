# Osmo Nano 批次状态与低同质化

本参考用于 4 个以上链接、跨批续写或用户明确要求低同质化的任务。阈值是复核护栏，不是新的配额模板。抖音、小红书与 B站实时采集必须先遵循 [统一读取 Skill](../../read-social-links-with-social-helper/SKILL.md)，本参考只消费其证据包。

## 每批只同步一次

新批次开始时，按 [op-sync.md](op-sync.md) 判断是否需要刷新 op。将本批采用的规则压成 `op_style_snapshot` 写入 `nano_comment_state.json`，随后冻结；新增链接沿用该快照，除非用户在当前任务给出新的明确纠偏。

op 不可用时使用 [op-style-baseline.md](op-style-baseline.md)，把快照状态标为 `cached_fallback`。风格源故障不能覆盖当前用户要求，也不能阻塞已有充分证据的链接。

## 证据胶囊

每个链接记录：

```text
原序号｜平台｜作品ID/规范链接｜可读状态｜确认型号
锚点ID与证据｜事实边界｜证据级｜用户缺口｜产品机制
可感收益｜购买阻力｜可达S级｜原话/限制｜媒体路径
```

短帖只有一两个锚点时允许复用锚点，但三组要改变关注任务或立场；不得补造第三个画面。

## 滚动账本

只保存最近 30 个链接的摘要与文本指纹，不持续保存旧全文：

```text
锚点ID｜关注任务｜语气/知识水平｜开头类型｜去产品词前6字
句长档｜标点签名｜产品称呼/位置｜回复数｜互动路径｜文本指纹
种草机制｜购买阶段｜受众视角｜证据级｜实际S级
```

优先检查以下模式：

- 同一精确开头跨多个链接第三次出现；
- 三条主评同时拥有相近字数、相同标点或相同回复数；
- 连续链接复用同一“视角＋场景＋阻力＋机制”；
- 产品词总在句首、同一组别或同一语法位置；
- 楼中楼持续复用“接梗—科普—反驳—收束”；
- 一个具体问题被多条回复同义扩写，却没有新增立场或分歧；
- 同一链接多组反复使用“看不出来、先别下结论、等实拍”；
- 竞品一出现就用“目的不同、各有用途、看需求”做万能平衡收束；
- 同一句骨架只替换产品名、物件或近义词；
- 滚动 10 个链接中同一种草机制出现超过 4 个链接。

阈值命中先复核证据与语义。素材确实只支持同一种机制时可以保留，但应改变具体缺口、立场或互动入口，并在状态中记录例外。

## 分块提速

- 复用统一读取 Skill 的逐链接账本、成功/失败状态和证据包；不得在本参考中重新定义批次、并行、补抓或重试。
- 多于 8 个可读链接时按 6–10 条分块。主任务先做互斥分配，给每块预留不同的高频语气、开头、产品位置、互动路径和种草机制，并列出本块禁用组合。
- 各块只共享证据胶囊、快照摘要、账本计数和禁用组合，不共享大段旧评论全文。
- 合并后检查跨块重复，只局部重写命中组。已成功抓取、已核验的型号和媒体不重复读取。
- 已抓成功项先写先交付；失败项单独列入 `failed_ids` 或 `unresolved`，不拖住整批。

## 状态文件

按 [../assets/nano_comment_state.template.json](../assets/nano_comment_state.template.json) 在批次工作目录创建 `nano_comment_state.json`。它只保存：

- 规则版本、产品范围与 op 快照来源；
- 输入、证据、媒体、草稿和成品路径；
- 成功、失败、待补抓和已交付序号；
- 分块互斥表与滚动账本摘要；
- 种草机制、受众视角、证据级和 S 级分布；
- 链接专属性、产品因果、用户收益、表达可信度与去 AI 复核；
- 未解决问题。

不得保存账号、Cookie、Token、密码、会员会话、旧评论全文或完整抓取日志。

## 重写顺序

命中同质化或 AI 痕迹时依次尝试：

1. 换关注点、任务或立场；
2. 换信息出现顺序与开头；
3. 删掉完整解释或总结；
4. 调整句长、停顿和结尾；
5. 改产品称呼与位置；
6. 改楼中楼入口，让讨论自然停在不同位置。

只换同义词不算修复。任何改写都不能丢失真实锚点、越过证据上限或补造用户经历。

## 批量纯净格式

为便于续接与核对，批量文件使用：

```text
## 原序号｜规范链接

主评论：……
↳ 回复1：……
↳ 回复2：……
```

每个链接仍有 3 组；回复数量按语境为 2–4 条，不为机器格式制造固定节奏。
