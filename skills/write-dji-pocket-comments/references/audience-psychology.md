# Pocket人群与心理参考

本参考用于挑选观看位置与开口理由，不用于制造发布者身份
区别体现在回应什么、为什么想说、有什么情绪，不靠自报职业、年龄或虚构持有经历
数量、点名、格式见 [SKILL.md](../SKILL.md)，七类型与带前提教学例见 [style-examples.md](style-examples.md)

## 动态选角

1. 从原帖主题、情绪和一个动作、原话、拍法或设置讲解出发，找值得回应的地方，不先定人设再套内容
2. 按原帖选择表达目的，可以接情绪、问未说清的事、轻调侃或联想怎么用，不让所有视角都收成“我也想用Pocket这样拍”，也不统一索要教程、机位或参数
3. 每条只抓一个主要反应，可以是期待、心动、被帮到、懊恼、好笑或被触动，允许停在念头，不写满背景到购买的闭环
4. 先找不同的主导表达，再决定每帖写2–4条主评与各条语气；2条是正常交付，无需`reduced_output_reason`，不为三条或四条拆分同一个意思。七类型标签不同、换了画面或换了身份都不能代替实义差异，也不固定“新手＋老用户＋理性派”
5. 自然点名与无名画面反应随内容混合，不固定“两条点名＋一条无名”的数量或位置；实际点名时围绕同一目标型号变化称呼，未知型号用Pocket、大疆Pocket、DJIPocket；本人型号由真实材料确认时可以谈本人设备，不据此认定博主的机型
6. 真实个人材料只绑定其发布者，不能把一份家庭、旅行或持有经历拆给多个账号冒充不同真人；多视角是候选表达角度，不是捏造多个身份的授权

## 从人群关注点找到需求和情绪

下表描述可选视角，不是可直接粘贴的身份模板
没有真实个人背景时，保留当前想法或明确假设，不写已经发生的经历与确定行程

| 视角 | 原帖触发点 | 可写的使用需求与情绪 | 需要真实材料才能加入的部分 |
|---|---|---|---|
| 刚接触拍摄的人 | 设置或操作被拆成清楚步骤 | 终于知道从哪开始、想马上试一段、教程来得及时 | 刚入手、持有型号、之前操作失败、已定出行 |
| 独自拍摄关注者 | 博主演示走进画面或给自己留背影 | 想让自己也出现在记录里，不再只想到拍风景 | 独自出游、过去没拍到自己、拍摄结果 |
| 手机拍摄者 | 原帖展示导航、看菜谱和拍摄的分工 | 想把当前要做的事与记录分开，减少手忙脚乱 | 自己被打断的经历、手机型号和真实实测 |
| 升级心动者 | 有证据的新旧对比或换机后的记录 | 某个真实用途让换机期待更具体，可以只心动 | 自有旧机、升级计划、体验与性能差异 |
| 旅行记录关注者 | 早市、车上聊天、等车或景点之间的小片段 | 想把路上也留下，期待具体一幕 | 城市、日期、同行者、确定行程 |
| 家庭或人物记录关注者 | 念叨、害羞、轮流拍摄、没剪掉的笑声 | 想留下一个平时忽略的样子，被小细节触动 | 亲属和伴侣关系、家人习惯、家庭活动 |
| 宠物画面关注者 | 开罐头前、耳朵动了、等待和跑偏 | 想提前开始录，避免只顾笑错过那一秒 | 自己养宠、宠物习惯、既往拍摄失败 |
| 普通日常关注者 | 买菜、吃烤红薯、关灯出门、整理房间 | 发现普通生活也有想拍的片段，突然想试 | 设备吃灰、下班安排、搬家计划 |
| 学习或练习关注者 | 舞蹈、弹琴、手工的前后过程 | 想把还不熟练的版本也留着，好笑或有盼头 | 正在学习的项目、进度、作品或练习结果 |
| 演出与活动关注者 | 等开场、同行者反应、散场聊天 | 想记录活动周边的小片段和当时心情 | 票、场次、座位、准入、拍摄与收音结果 |
| 小店与单人创作关注者 | 忙乱的准备、布置、试拍或重录 | 想记录自己的制作过程，或知道第一段拍什么 | 店主身份、业务、客户、账号与订单 |
| 后期整理关注者 | 排素材顺序、保留失败、前后对照 | 觉得积压素材有了去处，想保留以前会删的片段 | 现有素材、真实剪辑习惯、软件操作和结果 |

不能因为原帖没有直接功能演示就退回通用赞美或硬问参数
视频的实用价值可以触发真实使用需求，但教程有用不等于设备无需学习，成片感人也不证明某项硬件优势
有证据的功能收益再进入S2/S3，单纯点名、心动或需求联想不自动提高种草等级，详见 [product-seeding.md](product-seeding.md)

## 情绪和类型怎么选

| 反应或类型 | 成立条件 | 写作落点 |
|---|---|---|
| 被帮到 | 视频恰好回答真实顾虑 | 来得正好、终于知道怎么开始，不硬补参数解释 |
| 升级对比 | 新旧关联真实，或材料确认正在考虑更换 | 用途触发期待，不算预算、劝退或和博主较劲；不捏造升级收益 |
| 具体经历 | 发布者提供对应真实经历 | 留一个动作或小失误，让视频接住它，不写履历 |
| 意外惊喜 | 原帖确有原先没想到的记录机会 | 发现还能这样拍，不靠夸张词替代具体细节 |
| 欲扬先抑 | 发布者的畏难或预期有依据 | 自己从不敢试到想试，不编产品缺陷，不评价博主水平 |
| 深度认知 | 原帖引出一个被忽略的小细节 | 想多留哪一段、以后改哪个动作，不上升成人生总结 |
| 经历＋对比 | 同一发布者的真实前后经历 | 比较拍法、习惯或生活变化，不必变成机型测评 |
| 纠结下单 | 有具体用途让当前兴趣更强 | 允许期待、犹豫或想先试，不强制买、不强制购前提问 |
| 好笑与轻调侃 | 动作、原话或可见评论提供语境 | 接住一次就停，不编熟人关系，不嘲讽或拆台 |

不要每条加“救命”“谁懂”“哈哈”或表情来证明有情绪
也不要每条都写成“本来……看完……终于……”或“刚买＋出游＋怕不会”，同一种心理可以用不同长短、句式和停顿表达
七类型是素材与情绪参考，可能重叠，不是每帖配额或主导表达的分类标准；实际开口理由重复就重选，有两个成立的表达就写两条，不填满四条

## 主评与回复的自然关系

- 同帖每条有不同的想说这句话的原因，不按主评数量凑职业、句长或标点组合
- 主评可以是直接感受、一个拍摄念头或带真实材料的短经历，不强制问题、争论、功能总结或购买结论
- 每条主评配0–4条回复，一句已成立就不配回复，接一句足够就停。内部先明确谁回谁，再接住实际父句的问题、调侃或情绪；不强制第二条接第一条，多条回复仍不能只是各说各的旁白，详见[互动对话](reply-dialogue.md)
- 主评者回来可沿用自己的真实素材，其他观众不能借用；说话者按内容选择，不固定A→B→A或A→B→C，也不必每组安排问答、反方或科普
- 楼中楼只写用户侧成立的接话，不替博主回答，不用虚构另一位已购用户来为主评背书
- 提问只在确实缺少某个信息且这个问题本身自然时使用，不把所有使用需求改写成索要花絮

## 真实性与交付检查

- 第一人称的当前想法可以直接表达，购买、持有、家庭、职业、行程、使用结果等事实只从相应发布者提供的真实材料取用
- 假设教学案例必须标明假设并列清前提，不能因范例写得自然就转成可发布的真实证言
- 不虚构第三方背书、竞品故障、销量、作者关系或商业结果，不制造“大家都买了”的共识
- 楼中楼是文案草稿，不是安排账号造势的授权，也不以普通消费者经历掩盖真实商业关系
- 每条在内部能定位原帖触发点，短反应可省略原帖已给的画面描述；实际提到产品时与当前讨论有关，无名画面组不硬补型号，各条有不同主导表达，不能只换简称
- 真实材料不足时缩到当前念头，不强补家人、宠物、假日或城市；有两个成立角度就交付两条，不为数量补泛夸
- 最终交付用编号主评与缩进回复，不展示角色标签、类型或分析说明；主评和回复正文无中文句号或句末英文句点，编号句点不属于正文，英文产品名与型号内部无空格；问号、感叹号、逗号和表情随语气使用
- 跨帖复核开头、关注点、情绪、产品位置和接话走向，删除第二遍解释与结尾总结，不把情绪写成新的固定模板
