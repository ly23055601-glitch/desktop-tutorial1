# Pocket同帖与整批差异（LH12）

每次写作均读取，同帖差异从一个链接开始检查；4个以上真实链接或跨批续写再维护整批账本。写作逻辑见 [入口](../MODULE.md)，证据字段见 [需求与产品证据](product-seeding.md)。采集仍以 [统一社媒读取技能](../../read-social-links-with-social-helper/MODULE.md) 为唯一规则源。

## 选材与分配

每帖先概括主题、可见情绪、可接细节及产品关系，找出成立的表达，再决定写2–4条主评，为实际各条记录“主要想说什么”。同帖各条要有不同主导表达；只换镜头、衣服、地点仍都在说“我也想照着拍”时重选。可围绕同一细节产生不同表达，不按预设数量拆画面或拆同一个意思。每6–10个链接检查一次整体组合，不能每帖都排“感叹＋问题＋使用需求”。

多样性不依赖制造人群。没有个人经历时可回应原话、接住情绪、轻调侃、交流未说明的内容或提出当下念头；真实经历只给提供它的说话者使用。

记录每条的：

```text
链接/主题与情绪/锚点｜个人材料来源及说话者｜主导表达｜产品关联
主评前6字｜主要句式｜产品称呼和位置｜回复speaker/reply_to/response_move｜文本指纹
dominant_expression｜product_connection｜claim_mode｜need_connection（仅需求型）｜实际S级
```

- 七类写法是素材、心理和修辞参考，标签会重叠。分别标惊喜、欲扬先抑、具体经历不等于说话目的不同，不给每帖固定配新手、老用户、理性派或反方。
- 同帖产出2–4条主评，每条按话题配0–4条回复。有两个自然表达就写两条，第四条只有独立的开口理由才加入，不为数量补泛夸、问题或使用计划。多个角度可共用一处视频细节，但关注的事要不同，不能只换产品名。
- 不给整批设置claim_mode或S级比例，多个链接同属一种证据模式可以成立。但同帖各条若都落在同一个“以后照着拍”的目的，必须重写重复组；模式不同也不能豁免语义重复。
- 留意“刚入手＋要旅行＋不会用＋来得正好”是否成了全批骨架，以及是否每条都以“本来、看完、原来、救命”接相同转折。
- 不按字数、标点、表情、昵称或句长配额硬调。情绪、长短和完整程度跟着这句话实际想说的事走。
- 同一批反复“产品名＋这条/这段/这组＋画面评价”仍是开口套路。改写时删掉可省的画面复述和理由，把真正的反应留下；不能只移动产品位置或给句末换一个标点。
- 主评一句已经成立就不配回复，接一句足够就停，有需要继续聊的内容才展开。说话者随实际回应选择，不固定ABA或ABC；多条回复也不强求角色轮流出现。同批检查是否反复建议加认同、B指导拍法而A改步骤、问已回答的问题；托脸、扶帽、捋头发若都在说“手不知道往哪放”，仍是同一个笑点。
- 自然点名与无名画面反应随内容混合，不再固定“两条点名＋一条无名”，也不以位置或比例制造差异。只对实际点名的评论检查称呼变化，同一目标型号不为换称呼改代际；未知型号可用Pocket、大疆Pocket、DJIPocket。无名组不在回复里补型号来完成任务。

并行前共享各帖主导表达组合、高频顾虑、笑点和回复走向，给各块分配不同的表达入口，注明哪些真实材料属于哪个说话者。合并后必须再做全批语义复核，不能把各块局部通过相加视为整体通过。滚动保留最近30个链接或150条主评、450条回复的摘要与指纹即可。

## 状态与交付

新批次使用 [状态模板](../assets/pocket_comment_state.template.json)，`rule_version=2026-09-05-LH12`，`claim_registry_version=2026-09-02-LH5`。保留输入材料定位、证据文件、链接分配、草稿路径、成功/失败/停止记录和QA结果。

- `delivery_mode=with_replies`允许每组0–4条回复，`main_only`各组均不附回复。每帖主评为2–4条，2条无需`reduced_output_reason`；数量相同本身不是同质化错误，不要求每批刻意覆盖所有数量组合。
- 模板只有一个可复制的组结构和空回复数组，不规定交付数量；状态只保留实际组与回复。完全没有合理话题时登记停止理由，不生成凑数评论。
- 每组 `main_anchor_ids`恰好一个，`main_moves`记1–2个主要表达动作。自然叙述中多个背景片段不等于多个营销动作。
- 每组 `dominant_expression`用短话概括实际主要想说什么；整组出现产品名、产品能力或因果断言时填写`product_connection`，说明与锚点的关联。整组仅聊具体画面的observed/S0可留空，不新增分类。不得把标签改得不同就声称内容不同；`claim_mode`和S级按正文判断，不预填为需求型。
- `seed_layers`只记录实际种草层，主评最多两层；need/reaction的叙述不要把心理放松误记成产品硬件收益。
- `personal_need`用 `need_connection`记录视频如何触发需求；主评引用真实经历时写本组 `personal_context`。其他回复者首次使用经历时在 `reply_personal_contexts`按实际回复序号绑定自己的材料；同一说话者后续可沿用，A回来可沿用主评材料，不跨组或说话者授权型号或经历。
- 每组有回复时填写`dialogue`，内部`reply/speaker/reply_to/anchor_quote/response_move`按最终稿回复出现顺序一一对应。首条回复主评，后续指向实际父句，不强制有回复接回复；仍须语义复核是否接住上一句、是否平行旁白或不必要的延长。零回复可省略`dialogue`或使用空回复数组，不保留旧回复记录与`reply_personal_contexts`；单回复无需补第二条。具体契约见[需求与产品证据](product-seeding.md)，语义验收见[互动对话](reply-dialogue.md)。
- 最终交付采用编号主评与单层缩进回复，不展示A/B角色、类型或分析标签；每帖从`1.`连续编号。检查器直接读取这份最终稿，不另存一份带标签的审核正文；若材料保留旧标签，标签仍与内部映射一致。第四组与前面各组执行相同的事实、来源和语义检查。
- `strong_seed_group`默认null，不强制分配S2/S3；声明强组或实际写能力时仍遵守完整事实与因果门禁。
- 无硬件证据但有真实需求联想的链接可正常交付S1；有真实单锚点、已并排复核的内容互动可交付observed/S0，纯画面组不要求名称或产品关联说明。这两者均不因无强卖点登记停止；完全无合理话题时停止植入。所有组仍检查主评及各回复的硬件事实和因果，产品关联说明不是事实证据。
- 实际S级显式记录，不用产品词或购买词次数推断，也不把S1视为文案不合格。

`capture_policy`和`capture_attempts`只镜像统一读取技能结果，不改变其节流、问题交人工或一次证据验收规则。状态不保存账号、Cookie、Token、密码或含鉴权参数的完整链接。

每个allocation的id对应作品ID，无法稳定抽取时填写去查询参数的canonical_url。多个文件都从章节1开始时还须填写draft_path，避免证据串帖。官方claim、操作—结果与混拍证据格式见product-seeding参考。

## 机器检查与人工复核

```bash
python3 scripts/check_comment_homogeneity.py draft.md --state pocket_comment_state.json --product-policy off --seeding-policy strict
```

跨批加 `--baseline recent.md`；历史文件只用于比较，不当作当前结构错误。整批没有可写评论时只记录逐链接停止理由，`qa.checker_status=not_applicable_no_copy`，不对空文件运行正文检查，也不把未运行写成通过。输出机器结果可加 `--format json`，查看单条可加 `--verbose`。不要例行加把全部文风预警变为错误的全局 `--strict`。

新版本由LH12状态启用；LH5–LH11历史批次保留原数量、标签和来源行为，无需批量重写。自然点名没有固定位置或比例，不恢复旧版硬性两明一隐及回复补名规则，LH7及后续状态本已忽略旧`--product-policy`开关。主回复无句号、禁Osmo和英文名称内部空格仍是正文硬性要求，主评编号的句点不计入正文，来源与技术文件中的官方名称不删改。

重点复核：

- 去掉产品名、标点后相同，或只换数字/型号的评论，必须重写
- 无名评论保留可回查的原帖锚点，正文不必重新描述画面。短反应、省略和一句结束可以成立；结合原帖判断是否有开口理由，批量套用的泛夸应重写，不用补细节或型号掩盖空泛
- 相似度、前6字、产品位置、逗号比例、句长或短回复频次的提醒是查重线索，不证明文案差，也不自动要求补字、改标点或加问题
- “处境→反应”可自然连贯，不能把它误判成必须拆开的广告链；真正需要重写的是画面复述、功能说明、收益总结与催单一起堆进一条
- 每条是否都有不同的“为什么要说这句话”，而不是不同口头禅；情绪是否来自视频和个人材料，而不是硬加哈哈或表情
- 先把同帖实际各条的产品名、具体景物暂时略去，口头概括每条在做什么。概括后都是“我也想模仿”或“不会摆姿势”时换表达目的，不能只把想改成打算、试试、要是
- 不让“较真、算预算、劝退、强行纠错”挤掉用户想要的情绪接话；真实产品错误仍按证据处理
- 楼中楼是否答到父句所问、接住父句的调侃或情绪，是否只是加了角色标签的两句平行旁白；引用了上一句不等于互动成立
- 同一人回来时身份与已给事实是否连贯，是否复制“同意→科普→但也有局限”，是否借回复制造博主回答或另一段虚假经历

命中后优先换主导表达，选材重复再换关注点，然后改句子入口、节奏和情绪，最后才调名称与位置。只换同义词不算去重，任何改写不能删除真实锚点或添加不存在的背景。

## 完成标准

在 `qa.semantic_review.diversity_review`逐帖记录`id`、`verdict`（passed或revise）、`comparison_reason`，对照各组dominant_expression与正文说明实际差异，并检查回复推进。比较覆盖实际2–4条主评及其0–4条回复，2条无需减量理由，零回复和单回复不因没有完整对话链被退回。“画面不同”“没有字面近重复”不是足够的通过理由。待改组修订后重新复核；机器能查映射、记录完整和明确重复，不能证明自由文字中的语义差异。

交付还须复核原帖主题与情绪、个人来源、产品关联、格式和跨帖笑点/回复走向。多个文风预警汇集时应一起审视真实重复，不能用一条泛泛说明统一放行，也不为清零预警机械改标点。

采集问题只按统一读取技能保留原序号交人工，不自动重读；写作警告只重写相关组，已经取得的材料直接复用。用户仅要讨论风格案例时，直接标明假设材料并做上述语义/格式复核，不构造假的批次采集文件。
