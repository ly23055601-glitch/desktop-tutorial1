# 360／oq：空间视角、拍后选择与真实使用表达

补充日期：2026-09-08。来源：本任务用户对后续材料的明确要求。**空间视角与拍后选择是优先补强方向，其他卖点与使用兴趣继续开放。**现有[18项卖点](../selling-points.md)和[48张场景卡](../scenario-bank.md)用于查知识、提出解释；真实使用感受需要具体材料支持，不能从SC假想场景中反推。

五个品线共用的原话、讨论、使用阶段与逐句反馈收录方式，见[共用体验材料指南](/Users/luocaihua/.codex/skills/write-consumer-comments/references/experience-materials.md)。本页只补360的观察重点。**材料可以完整，评论只取其中最值得说的一点。**材料整理不等于现在必须写成评论；实际成稿按[项目共用写手入口](../../../.agents/skills/write-consumer-training-comments/SKILL.md)当前规则执行。

<a id="one-work"></a>
## 围绕同一份作品，留下四种能互相对应的材料

最有帮助的是看到“拍到了什么、最后选了什么、为此做了什么、本人为什么偏爱它”。不要求提供者先写测评，也不要求每份材料都齐全才收录；缺少的部分明确留待补。

| 材料 | 尽量保留什么 | 能帮助理解什么，不能替代什么 |
|---|---|---|
| 原始全景素材 | 原文件或实际可访问的位置、片段起止、准确型号与模式的已知信息；文件名保留对应关系 | 观察记录范围与后续选择的关系。平台成片、播放器录屏、代理或抽帧各自注明，不能替代未取得的原文件 |
| 不同取景的结果 | 优先同一原片同一时间段的两个实际导出版本；若另改速度、调色、声音或时长，注明变化 | 比较人物大小、环境比例、观看方向、视角变化和叙事重点。不同时间段或不同拍摄不能冒称只改变取景的对照 |
| 必要的处理过程 | 实际用的手机／电脑、软件与版本（知道才填），怎样导入、选取视角、剪辑或导出；已有录屏或几句说明即可 | 分清现场决定与拍后决定，找到真正需要人工判断的步骤。没有过程材料时不从漂亮成片猜作者按过哪些按钮 |
| 使用者自己的偏好 | 他偏爱哪个版本、喜欢哪里、什么用途下会选它；保留原话及它指向的文件／时刻 | 学习审美、使用意图和语气。作者选择不等于设备普遍更好，也不能代替另一人的喜欢或处理成本 |

只有一个导出也值得收：可以学它的空间关系和使用者感受，但不能据此确认原始记录范围或另一版本效果。没有偏好原话，可记录编辑观察，不能代说“作者更喜欢A”。只有口头说明时保留为本人自述，不标作已看过实际操作。收到文件仍须区分“已收到”“实际看过／听过的范围”和“已经确认的结论”。

型号不确定先记不确定。技术核验按任务回到[后期模块](../modules/04-postproduction.md)、[全景取景SP01](../selling-points.md#sp01)、[自拍杆SP02](../selling-points.md#sp02)、[完整流程SP17](../selling-points.md#sp17)及相应事实卡的官方来源；这些入口中的历史核验日期不会因为本页更新而刷新。本页没有新核验参数或软件能力。

<a id="observe"></a>
## 观察画面时，多问“偏爱在哪里”

以下是可选择的观察与交谈方向，不是逐项采访问卷，也不是对原作者的预先结论。已有一句自然感受时，先保留，不把它扩写成原因完整的产品分析。

| 观察方向 | 可以留意的具体区别 | 值得保留的使用分歧 |
|---|---|---|
| 自己在空间中的位置 | 更重人物还是环境；人物从哪个方向进入；回看能否理解人与地点的关系 | 有人喜欢自己明显出镜，有人更喜欢人物只是环境中的一部分 |
| 人与人的关系 | 单独看讲述者，还是把回应者和共同活动放在一起 | 有人追求明确主角，有人珍惜旁边的反应；不能预设哪个版本更高级 |
| 观看方向与节奏 | 固定视角、缓慢变化或较强变化，分别让人注意什么 | 有人喜欢新鲜的观看方式，有人想安静看清一段动作；主观不适不自动成为普遍性能结论 |
| 拍后选择带来的感受 | 当时就知道要拍什么，还是回看后才找到偏爱的方向 | 有人喜欢保留选择，有人觉得筛选负担增加；省掉现场取舍不等于全部后期消失 |
| 完成这一段实际花的力气 | 哪一步顺手、哪一步重做、什么因素导致等待 | 分清首次学习、常用流程与设备处理等待；单次用时不是所有人都能达到的效率 |
| 哪种时候想起拿出来 | 一次共同出行、反复练习、临时停留，或已有拍法缺少某种画面 | 喜欢成片、愿意经常携带、愿意整理是不同事情，不必有统一购买结论 |

人物熟悉度沿用[使用阶段指南](../../../.agents/skills/use-osmo360-knowledge/references/audience-guide.md#stages)。可以仅记“刚第一次尝试取景”“平时只剪一小段”“还在比较已有设备”；这些比单写职业或年龄更能帮助理解关注。阶段未知就留未知，不凭一句术语判断老手，不从标签推断心理。

<a id="types"></a>
## 在已有帖子类型下补一个完整例子

继续使用[当前帖子类型表](/Users/luocaihua/.codex/skills/write-consumer-comments/references/post-type-selection.md)及原分类出处，不重标历史表、不重采历史链接。以下为优先尝试的材料搭配，类型不限制能讲哪些卖点；实际归类仍看作品的主要内容。

| 常见类型 | 可以补的材料 | 可能学到的一点 |
|---|---|---|
| 成片与作品展示 | 完整作品，已知型号／处理说明，作者对某个视角的原话；有对应原片和另一导出则一起保留 | 为什么喜欢这样的空间关系；产品语境明确时，直接喜欢已展示的结果也可以成立 |
| 创意玩法展示 | 效果所在的完整片段，实际制作说明，使用者尝试后的几句反应 | 兴趣来自结果、尝试过程还是特定观看方式，不把全部效果归作机内一键能力 |
| 拍摄与剪辑教学 | 完整教学、原片与导出的实际对应、已有步骤说明和提问上下文 | 新手在哪一步刚理解，熟手省略了什么；不要求评论把教程重说一遍 |
| 生活与过程记录 | 一次活动的完整叙事，什么时候拿出相机，拍后留下的随口感受 | 为什么这次想到使用，哪段共同经历值得保留，不固定写成便携或怀旧 |
| 测评与使用反馈 | 测试对象与条件、作者实际自述、偏好不同的主评和回复 | 哪些条件与自己相近，哪些只是个人偏爱；不以高赞或用户自述替代产品证据 |
| 对比与选购建议／提问与求助 | 原问题、已有设备与阶段信息、原回复关系和实际结束位置 | 当前真正想改善哪一步；自然讨论可以没有统一结论，也不编博主解释补齐缺口 |

如类型暂定、混合或未判定，沿用当前标记；有一条有用的原话不等于已理解整帖。空间视角以外的画质、色彩、收音、携带、维护等兴趣同样可收，按实际材料查对应SP。

<a id="small-note"></a>
## 不用做重表，附几行说明即可

这是**可选收录便笺**，没有最低文件数或原话数量。原文件、消息导出和讨论已说明的信息不重复抄写，短缺不填想象值；不为每条新素材创建空目录和空记录。

```text
作品／文件位置：
已知产品与使用阶段：
原片—导出对应、必要处理说明：
使用者原话／完整讨论位置：
明确反馈：哪一句保留或不保留，谁在何时怎么说的
本次实际看过／听过的范围与还缺的内容：
```

默认原文件留在已有位置，在便笺中引用；无需把大视频重复复制进知识库。语音先保存原音频，转写与不清楚的部分分开标；聊天保留前后语境。讨论保留原帖、主评、回复对象和必要先行句，原楼只有一句附和也不虚构后续，不把按热度排序当作对话顺序。

用户明确认可哪句就记哪句，并绑定原上下文；“这里解释太多”只覆盖指出的部分，不能扩大成整楼禁止解释或整篇已认可。未收到具体评价的材料保留未反馈，助手觉得自然只记编辑判断。

<a id="learning"></a>
## 从完整材料选出一次表达

先看作品和原话，再看编辑解释。可以选人物与环境的比例、一次拍后重选的惊喜、仍觉得原来拍法够用、或处理时真正卡住的一个环节。能说清当下产品兴趣就可停；有作用的细节可展开，长度不预设。

同一份作品可以触发不同偏好，但每位消费者不必复述“背景＋场景＋卖点＋总结”。真实使用者的说法用于学习关注、直接程度和接话原因，不能把原句换型号批量套用。新训练人物不能替原作者说明未知的模式、画面、声音或偏好。

课堂可先看两个已有导出，再听使用者原话，看自己是否猜对偏好；只有一个版本时，只围绕实际材料讨论。无偏好原话时，这个练习停在编辑观察，不编标准答案。真实短讨论用来学习如何接话与在哪里自然停止；本轮不是新稿批次，不计每日产量，新稿教学完整度仍按共享技能当前要求判断。

已有可直接用于阶段辨认的[两次试机材料](../materials/first-use.md)：M07明确自述初学，并同时表达想试动作与手机剪辑负担；M08称新机首测和当次满意，但未说明摄影熟悉度。二者不可拼成新手到熟手的成长故事，也不能用两件不同条件作品比较产品表现。该页保留原话、上下文、实际看图范围与四个理解检查。

当前9份已存材料与缺口见[本地材料盘点](../materials/STATUS.md)，其中M09是购买后按动作练习的局部教学观察。收到新社媒链接并需要读取时，按项目统一采集技能一次处理当前完整集合；本页不另建采集、节流或重试规则。真实原素材不足时先用现有材料能支持的部分，不以官方参数或合成评论伪装真实体验补齐。
