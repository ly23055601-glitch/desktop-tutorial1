# Osmo 360 项目知识与人群入口

本入口使用当前项目文件，不依赖历史聊天。范围包括 Osmo 360、Osmo 360 II，以及资料库中的 Insta360 X6、X5、GoPro MAX2。默认简体中文、中国大陆环境；保留海外资料地区和核验日期。

## 按当前任务取用

- **功能问答、两代差异、拍摄后期、竞品比较或培训**：先读[知识库索引](knowledge/INDEX.md)，再查相关型号、模块和事实卡。无需通读全部资料。
- **产品卖点、用户价值、这个角色适合讲什么或是否值得升级**：读[卖点与用户价值](knowledge/selling-points.md)，按五组主题、具体型号或角色任务找条目，再打开所引事实卡及相关心理假设。先说明能帮助完成什么、为什么可能有价值，再保留成立条件与价值不成立的情况。品类原理、本机能力、已证实差异分别表达；某代未确认不等于不支持。
- **使用场景更详细、发散卖点或为后续培训文案选材**：查[48张详细场景卡](knowledge/scenario-bank.md)，按具体事件选择SC，再由[任务变化与选材矩阵](knowledge/training/scenario-to-copy.md)反查主SP及H假设。读取单卡同时保留所在文件顶部的适用后期前提；材料允许发散，功能不扩展。只要选材时不自动生成消费者评论，不把144个角度当固定写作配额。
- **补充真实使用体验、空间视角与拍后选择材料、原话或完整讨论**：读[360体验材料指南](knowledge/training/experience-materials.md)和[现有材料盘点](knowledge/materials/STATUS.md)，关联同一原片、实际导出、已知处理与本人偏好；缺失不由成片倒推。该方向不限制其他卖点，材料完整不等于评论必须复述过程。这里只整理材料时不进入每日新稿统计。
- **谁会用、为什么买、为什么搁置、使用心理或表达分析**：读[人群与心理使用指南](references/audience-guide.md)，组合场景、需求假设、使用阶段及后期投入；需要解释产品如何帮助时再查精确型号的事实卡。
- **真实评论资料**：用户于 2026-09-10 停用本次接入的 Apify 付费采集工具；不再调用其话题发现入口。已有真实评论和来源可继续分析；需要读取抖音、小红书、B站时，将当前请求完整链接集合一次性交给[统一社媒读取](/Users/luocaihua/.codex/skills/read-social-links-with-social-helper/SKILL.md)。产品知识和默认培训路径继续使用，研究不计培训新稿 KPI。
- **主评论、回复、改写或案例示范**：先读[项目共用写手入口](../../writer-core/adapters/op/write-consumer-training-comments.md)，由共享消费者写作技能承担表达与检查；本库提供产品事实及角色假设。用户调用[360个人入口](/Users/luocaihua/.codex/skills/write-dji-osmo360-comments/SKILL.md)时保留其型号与证据边界。已读取的入口不循环加载，不复制另一套写作规则。
- **验收或维护**：按[维护说明](knowledge/MAINTENANCE.md)复核变化项，运行现有检索审计；心理假设与训练稿另行检查，不写进官方事实卡。

项目代码 `oq` 仍按 `AGENTS.md` 指向本入口。用户给 `oq` 加链接或材料要求新稿时，先按 `AGENTS.md` 进入每日培训入口，再由统一读取与本库选材接入共用写手；用户明确只分析、查询或维护知识时完成对应任务，不计每日新稿。卖点专题不是预制评论库，不要求把全部卖点塞进每条表达。

## 产品事实的使用

在项目根目录执行；不在根目录时先定位本技能对应的项目，使用脚本绝对路径：

```bash
python3 knowledge/osmo360/scripts/knowledge.py search '隐形 自拍杆 拼接' --model osmo_360 --format json
python3 knowledge/osmo360/scripts/knowledge.py search '跟随 导出' --model osmo_360_ii --format json
python3 knowledge/osmo360/scripts/knowledge.py search '续航 条件' --model insta360_x5 --format json
python3 knowledge/osmo360/scripts/knowledge.py search 'D2-024' --format json
```

按编号精确查卡时，每次传入一个完整卡号；多个卡号分别查询，不将空格拼接的编号当作批量精确查找。

1. 先确认型号。仅说“大疆360”或“360”时不要默认 II；泛讲可分别列两代，精确参数依明确型号回答。检索参数为 `osmo_360`、`osmo_360_ii`、`insta360_x6`、`insta360_x5`、`gopro_max2`。
2. 读取完整返回卡的 `statement`、`conditions`、`limitations`、地区、版本、来源定位和日期。`verified` 是当日官方资料支持，既不是实机测评，也不代表当前版本永远不变。
3. `pending`、`conflict` 只作相关缺口。没有命中先换主题词或查看模块／缺口；仍无依据就说明无法确认，不凭搜索空白断言“不支持”。
4. 产品断言进入正文前打开对应当前官方来源核对；若本轮已实际读取且覆盖该断言，不必重复读取。来源无法访问时明确只能提供带日期的历史记录，不能称本轮核验。产品更新、兼容性、导出与价格尤其保留当前范围。
5. 给出适用型号、模式、限制和事实卡编号／链接。重点区分全景球面规格与平面导出、防水与水下拼接、普通录像与特效、标称续航与实际续航。竞品没有同条件证据时只讲取舍，不判画质、散热或稳定性胜负。

## 心理解释和训练表达

心理指南是 `editorial_hypothesis / unvalidated`。先说可能发生的情境及矛盾，再说明表达线索和可验证问题；不从职业、年龄、消费能力或一句话断定心理，不编造占比、转化效果或真实研究结论。

历史[角色分析与8条示例](../../../outputs/osmo360/2026-09-06-audience-psychology/analysis.md)是待校准训练材料，按需查看，不当作认可范文或真实热评。新稿依共享训练契约另建人物与状态；不得将历史 `review` 或 `passed` 结果复用为本批结论。

产品能力以官方证据为准，假想角色的经历独立保存。实际产品断言按共享契约绑定 `product` 来源和 `product_fact`；本地事实编号帮助追溯，但不能替代实际读取的官方依据。Osmo 360 保留准确名称，不继承 Pocket 命名禁词或其他产品能力。

真实资料核验／旧稿审查沿用个人入口和共享库对应分支，不把旧稿改标为训练稿以绕过审查。新媒体原链读取遵循项目统一社媒技能，保持完整批次，不另设采集步骤。
